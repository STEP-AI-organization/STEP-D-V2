# 결제 메일 — 누가 무엇을 받나

> 2026-09-14 확정. 이 문서가 **정본**이다. 코드 주석은 여기를 가리킨다.

결제 한 건에 메일이 **두 종류** 나간다. 이름이 비슷해서 계속 헷갈렸고, 실제로 한동안
**같은 사람에게 두 통**이 갔다. 역할을 갈라 두었다.

| | 보내는 주체 | 받는 사람 | 내용 | 문구를 우리가 정하나 |
|---|---|---|---|---|
| **① 결제완료 알림** | KG이니시스 | **우리** (`contact@stepai.kr`) | 승인 사실(금액·카드) | ❌ 못 한다 |
| **② 결제 영수증** | **우리 서버** | 고객의 **결제 알림 이메일 목록** | 영수증 번호·크레딧·잔액·적격증빙 안내 | ✅ |

**①은 우리 확인용이다.** 이니시스는 판매자(우리)에게 "결제가 승인됐다" 를 알려 주는 것이고,
**고객에게 가는 문서가 아니다.** 그래서 그 주소를 소비자 주소로 두지 않는다.

**②가 고객이 받는 문서다.** 그리고 그 문서는 `/credits` 에서 내려받는 PDF 와 **같은 문서**다
(문구까지 일치 — `invoice-format-parity.test.ts` 가 고정한다).

---

## ① 이니시스 결제완료 알림

이니시스는 결제 요청의 `customer.email` 로 자기 메일을 보낸다. 그 값은 **부르는 쪽이
정하지 않는다** — `portone.ts` 가 PG 경계에서 우리 주소로 덮는다.

```ts
// billing-card.ts
export function pgNotifyEmail(): string {
  return (process.env.PG_NOTIFY_EMAIL ?? "").trim() || "contact@stepai.kr";
}
```

**왜 경계에서 덮나.** 이미 등록된 카드에는 예전에 입력받은 **구매자 주소가 저장돼 있다**
(`billing_card.buyer_email`). 등록 시점만 고치면 그 카드들은 계속 고객에게 메일을 보낸다.
발급·결제 두 호출이 지나는 자리에서 덮어야 **옛 카드까지 한 번에** 잡힌다.

바꾸려면 `PG_NOTIFY_EMAIL` env 하나. 코드를 고칠 일이 아니다.

⚠️ **소비자에게 이메일을 묻지 않는다.** 제품 결제수단 화면도 어드민 결제 시험도 구매자
**이름·휴대폰 두 칸만** 받는다(이니시스가 요구하는 필수값). 이메일 칸이 다시 생기면
그건 ①의 수신자를 고객으로 되돌리는 것이고, 두 통 문제가 재발한다.

## ② 우리 영수증

`invoice-email.ts` 가 보낸다. **크레딧이 실제로 적립된 자리에서만** 부른다 —
적립하는 곳은 셋이고 전부 부른다(`invoice-format-parity.test.ts` 가 강제):

- 자동 충전 (`auto-topup.ts`) — 잔액 0 이하일 때
- 수동 저장카드 충전 (`index.ts` · 지금 제품 화면엔 버튼이 없다)
- 운영자 결제 시험 (`card-test-charge.ts` · 어드민)

**받는 사람 = 결제 알림 이메일 목록.** `/credits` 화면에서 워크스페이스마다 등록한다
(`getBillingNotifyEmails`). 카드 등록자도, 계정 주인도 아니다 — **등록한 사람들뿐**이다.

⚠️ **목록이 비면 아무에게도 안 간다.** 몰래 다른 주소로 폴백하지 않는다("등록한
사람들만" 이라는 규칙의 당연한 귀결). 영수증 자체는 사라지지 않는다 — 인보이스는 서버에
남고 `/credits` → 인보이스에서 PDF 로 받을 수 있다.

실측(2026-09-14): `t_default`(STEPAI) 4명 · `1`(ENA) 2명 · `2`(test) **0명**.
test 워크스페이스에서 시험 결제를 하면 영수증 메일이 안 온다 — 버그가 아니라 목록이 비어서다.

## 발송 조건

SMTP 가 없으면 **조용히 건너뛴다**(발송 실패가 결제·적립을 막지 않는다 · `mailer.ts`).
현재 프로덕션은 Gmail XOAUTH2 (`SMTP_USER=hkj@stepai.kr` + `SMTP_OAUTH_*` 3종 시크릿).

## 바꿀 일이 생기면

| 하고 싶은 것 | 건드릴 곳 |
|---|---|
| 이니시스 알림을 다른 주소로 | `PG_NOTIFY_EMAIL` env |
| 이니시스 알림 자체를 끄기 | 이니시스 상점관리자 콘솔 (우리 코드 아님) |
| 고객 영수증 수신자 | `/credits` → 결제 알림 이메일 |
| 영수증 문구 | `invoice-email.ts` **와** `apps/web/.../invoice-pdf.ts` — **둘을 같이**. 한쪽만 고치면 파리티 테스트가 빨개진다 |
