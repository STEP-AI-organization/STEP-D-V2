# STEP-D 데스크톱 앱 — 설치 가이드 (사내용)

> 대상: 편집자·운영자. 개발자용 문서는 [native-desktop.md](native-desktop.md).
> 2026-09-01 기준 · **사내 검증용 v1** — 고객사 배포용이 아니다.

## 이 앱이 하는 일

STEP-D 화면을 그대로 띄우되, **영상 업로드만** 브라우저에서 앱으로 옮긴다.

| | 브라우저 | 데스크톱 앱 |
|---|---|---|
| 업로드 중 창을 닫으면 | **중단된다** | 계속 올라간다 |
| PC 를 재시작하면 | 처음부터 다시 | **끊긴 지점부터 이어서** |
| 네트워크가 끊기면 | 실패 | 복구되면 자동 재개 |
| 업로드 중 다른 일 | 탭을 못 닫음 | 앱을 닫아도 됨(트레이에서 계속) |

나머지(분석·추천·편집·배포)는 브라우저와 **완전히 같다.** 앱은 같은 화면을 띄운다.

---

## 1. 설치

1. 설치 파일 `STEP-D-Setup-0.1.0.exe` 를 받는다 (관리자에게 요청).
2. 실행하면 **"Windows의 PC 보호" 파란 경고**가 뜬다.
   → **추가 정보** → **실행** 을 누른다.

   ⚠️ 이 경고는 정상이다. 사내 검증용이라 **코드 서명을 아직 안 붙였다** — 서명 없는
   설치 파일은 Windows 가 무조건 이 경고를 낸다. 고객사 배포 전에는 서명을 붙인다.
3. 설치는 **관리자 권한이 필요 없다.** 내 계정에만 설치되고 바로 끝난다.
   바탕화면과 시작 메뉴에 **STEP-D** 아이콘이 생긴다.

## 2. 첫 실행

앱을 열면 STEP-D 로그인 화면이 나온다. 평소 쓰던 계정으로 로그인하면 된다.

**로그인은 한 번만 하면 된다** — 앱을 껐다 켜도, PC 를 재시작해도 유지된다.

---

## 3. 업로드하기

평소와 똑같다. 회차 업로드나 완성본 업로드 화면에서 파일을 고르면 된다.

다른 점은 **파일을 고르는 순간 창이 닫히고 위쪽 "전송" 버튼에 개수가 뜬다**는 것뿐이다.
브라우저처럼 진행률을 보며 기다릴 필요가 없다.

> 화면에 "앱을 닫거나 PC를 재시작해도 이어집니다" 라고 나오면 앱 경로로 올라가는 중이다.

### 전송 센터 (상단 "전송 N" 버튼)

진행률·속도·남은 시간이 보이고, 항목마다 이렇게 할 수 있다.

| 버튼 | 언제 쓰나 |
|---|---|
| 일시정지 / 재개 | 회의 중이라 대역폭을 비워야 할 때 |
| 취소 | 잘못 올린 파일 |
| 재시도 | 실패한 항목 |
| 파일 다시 찾기 | 원본을 옮겼거나 이름을 바꿨을 때 |

완료된 항목을 누르면 그 회차·클립 화면으로 간다.

---

## 4. 창을 닫으면 어떻게 되나

- **전송 중에 X 를 누르면** → 앱이 트레이(시계 옆)로 숨고 **전송은 계속된다.**
  다 끝나면 알림이 뜨고 앱이 스스로 종료된다.
- **전송이 없을 때 X 를 누르면** → 그냥 종료된다.
- 트레이 아이콘을 **더블클릭**하면 창이 다시 열린다.
- 트레이 우클릭 메뉴: **STEP-D 열기 · 모든 전송 일시정지 · 모든 전송 재개 · 완전 종료**

**"완전 종료"를 눌러도 전송은 안 사라진다.** 진행 중이던 것을 저장하고 끄며,
다음에 앱을 열면 끊긴 지점부터 이어간다.

미완료 전송이 있으면 **Windows 로그인 시 앱이 자동으로 뜬다**(백그라운드). 다 끝나면
자동 실행 등록이 저절로 풀린다.

---

## 5. 문제가 생기면

전송 센터에 사유가 한국어로 나온다. 대부분 아래 중 하나다.

| 표시 | 뜻 · 할 일 |
|---|---|
| 로그인이 필요합니다 | 앱에서 다시 로그인하면 **자동으로 이어진다.** 올라간 부분은 안 버린다 |
| 네트워크 | 연결이 돌아오면 자동 재시도. 기다리면 된다 |
| 파일을 찾을 수 없습니다 | 원본을 옮겼거나 지웠다 → **파일 다시 찾기** |
| 파일이 변경됐습니다 | 같은 이름의 다른 파일이다 → 원본을 확인하고 다시 찾기 |
| 회차 중복 | 같은 회차 번호가 이미 있다 → 프로그램 화면에서 확인 |
| 보안 저장소를 사용할 수 없습니다 | 앱이 업로드를 **시작하지 않는다**(안전 장치). 관리자에게 문의 |

그래도 안 되면 관리자에게 알릴 것 — 앱 이름·버전과 전송 센터에 뜬 문구를 그대로 전하면 된다.

⚠️ **큐 파일을 직접 고치지 말 것.** 앱 데이터 폴더(`%APPDATA%\STEP-D\transfer-queue`)에
전송 상태가 저장돼 있는데, 손으로 고치면 올라가던 파일을 잃을 수 있다.

## 6. 제거

Windows **설정 → 앱 → 설치된 앱 → STEP-D → 제거**.

제거해도 브라우저(stepd.stepai.kr)로 하던 일은 그대로 된다. 제거 전에 **전송이 다 끝났는지**
확인할 것 — 안 끝난 전송은 사라진다.

---

## ⚠️ 배포 전에 알아둘 것

- **사내 검증용이다.** 코드 서명·자동 업데이트가 없다. 고객사에 주기 전에 둘 다 붙여야 한다.
- **10GB 급 실파일로 아직 검증하지 않았다.** 재개 동작(네트워크 차단·앱 종료·재부팅)은
  단위·통합 테스트까지만 확인됐다 — 자세한 내용은 [native-desktop.md](native-desktop.md) 의
  "아직 검증 안 된 것".
- **현재 설치 파일**: `native/release/STEP-D-Setup-0.1.0.exe` (2026-09-01 18:36 빌드 · 106 MB).
  같은 날 오후에 고친 전송 결함 4건이 들어 있다 — 자세한 내용은
  [native-desktop.md](native-desktop.md).

### 다시 빌드할 때 — `pnpm dist:native` 가 리포 안에서는 실패한다

```
⨯ EBUSY: resource busy or locked, unlink '…\release\win-unpacked\resources\app.asar'
```

**리포 폴더를 감시하는 프로세스가 `.asar` 를 만들자마자 잠근다**(2026-09-01 실측 · Defender
실시간 보호는 꺼져 있고 STEP-D 프로세스도 없다 — 개발 워처가 유력하다). 새 출력 폴더를
줘도 같은 자리에서 막히므로 폴더를 지우는 걸로는 안 풀린다.

**해법 — 리포 밖으로 빌드한 뒤 옮긴다:**

```bash
cd native
pnpm build
npx electron-builder --win nsis -c.directories.output=/c/Temp/stepd-build
cp /c/Temp/stepd-build/STEP-D-Setup-0.1.0.exe release/
```

⚠️ 빌드가 조용히 낡을 수 있으니 **나눠주기 전에 시각을 대조할 것** — `release/*.exe` 가
`native/src/*.ts` 보다 최신이어야 한다. 아니면 이미 고친 버그를 그대로 배포하게 된다.
