# ENA 자동배포 오픈 계획 (2026-08-15 작성 · 목표 2026-08-2x 주)

> **파는 것은 도구가 아니라 결과다.** ENA 가 사는 것은 "AI 클립 편집기" 가 아니라
> **"쌓아만 두고 못 쓰던 아카이브가 알아서 배포까지 나가는 것"** 이다.
> 그래서 성공 기준도 추천 품질이 아니라 **손 안 대고 배포까지 갔는가** 다.

## 0. 구도 (사용자 확정 2026-08-15)

```
[AENA 기존 서비스]  ← 건드리지 않는다. 스키마·파이프라인 수정 없음.
      │  (새로 붙이는 것은 '자동배포' 기능 하나)
      │  HTTPS + 워크스페이스 API 키
      ▼
[STEP-D]  영상 접수 → 분석 → 추천 채택 → 렌더 → 채널 배포 → 성과
      │
      └ 정본 DB 는 STEP D 의 ENA 워크스페이스 (우리 운영자가 웹/admin 에서 지원 가능)
```

- **AENA 는 우리 입장에서 "외부 고객사 시스템"** 이다. 내부 호출 경로(`INTERNAL_API_*`)를
  쓰지 않는다 — 감사 기록이 남아야 하고, 다음 방송사도 같은 문으로 들어와야 한다.
- 통합은 **단방향**(AENA → STEP-D). 우리가 AENA 를 부르지 않는다. 상태는 AENA 가 폴링한다
  (아웃바운드 웹훅은 아직 없다 · §4).

## 1. ENA 가 영상을 넣는 법 (3안 — 하나를 골라야 한다)

| 안 | 흐름 | 장점 | 걸리는 것 |
|---|---|---|---|
| **A. API 인제스트** (권장) | AENA 백엔드가 `POST /api/factory/ingest` 로 회차 1건씩 | 사람 손 0, 대량 배치에 맞음 | AENA 쪽 클라이언트 구현 필요 |
| B. 유튜브 URL | `POST /api/factory/videos` 로 URL 투입 | 구현 가장 쌈 | **다운로드가 사무실 윈도우2 PC 전용 레인**이라 그 PC 가 꺼지면 멈춤 |
| C. 사람이 웹 업로드 | ENA 담당자가 stepd.stepai.kr 에서 직접 | 당장 되는 것 | 아카이브 대량에는 안 맞음 (첫 주 데모용) |

**권장: 첫 주는 C 로 시작하고 A 를 병행 준비.** 아카이브 물량은 A 가 아니면 감당이 안 되지만,
A 는 AENA 쪽 구현이 필요하고 아래 §2 의 차단 항목이 먼저 닫혀야 한다.

### 회차당 원가·소요 (실측 기준, 58.6분 회차)
- 분석 964초(약 16분) · 약 ₩285 · 자막 925 / 장면 12 / beat 245 / 쇼츠 20 / 검색 세그먼트 204
- **아카이브 100편이면 ≈ ₩28,500 · 순차 처리 시 ≈ 27시간** — 동시성 설계가 곧 납기다.
- 크레딧 단가는 `CREDIT_PRICE_KRW=28` 로 배포돼 있다(사업 확정 여부 확인 필요).

## 2. 오픈 차단 항목 (조사 결과 · ✅ 는 이번에 해결)

| # | 항목 | 상태 |
|---|---|---|
| 1 | **새 워크스페이스는 배포가 영구 403** — `ops_role` 을 주는 코드 경로가 없었다 | ✅ 해결 (0040 백필 + createUser/PATCH members, 프로덕션 ENA owner = `cp` 확인) |
| 2 | **웹 프록시가 고객사 키를 덮어써 문서상 인증 경로로 단 한 건도 성공 못 함** | ✅ 해결 (`x-api-key` 헤더 병행 수용) |
| 3 | **자동 게시가 `public` 으로 나감** — 채널 규칙의 privacy 를 아무도 안 읽었다 | ✅ 해결 (규칙값 우선, 기본 `unlisted`) |
| 4 | 실패·hold 잡의 **재시도 수단이 API 에 없다** | ❌ 남음 (M) |
| 5 | factory 상태기계에 **데드라인이 없어** 죽은 잡을 영원히 `analyzing` 으로 폴링 | ❌ 남음 (M) |
| 6 | factory 잡이 **배포 실패를 status 로 표현하지 않는다**(전멸해도 `done`) | ❌ 남음 (S) |
| 7 | 키 인증 401/403 이 전부 `request_failed` — 호출자가 재시도/중단을 코드로 못 가름 | ❌ 남음 (S) |

**4·5·6 은 같은 병이다:** 외부 호출자가 "끝났는지 / 실패했는지 / 다시 걸어도 되는지" 를
**우리 응답만 보고 판단할 수 없다.** 아카이브 대량 투입에서는 이게 품질 문제보다 먼저 터진다.
셋을 묶어 하나로 처리하는 것을 권한다:

```
GET  /api/factory/jobs/:id      → state ∈ {queued,analyzing,rendering,publishing,done,partial,failed,hold}
                                   + counts {clips, published, failed}  + lastError + stalledSince
POST /api/factory/jobs/:id/retry → failed·hold 만, 같은 mediaId 재사용(재과금 없음)
```
- 상태별 최대 체류시간(예: analyzing 90분)을 넘기면 `failed` + 사유. 지금은 무기한 재큐다.
- `done` 은 **한 건이라도 실제로 게시됐을 때만.** 전멸이면 `failed`, 일부면 `partial`.

## 3. ENA 가 결과를 보는 법

### 지금 있는 것
- **회차 상세**: 분석 진행률(단계별), 자막·장면·beat, 추천 목록, 미리보기·구간 재생
- **자동화 화면**: 규칙, 승인 대기(hold) 큐, **실행 로그(자동/수동 배지 구분)**, 오늘 게시 수
- **배포 탭**: 채널별 배포 기록·상태·실패 사유·재시도 버튼
- **영상 검색**: 회차당 200여 세그먼트를 인물·장면·대사로 질의 (제품의 목적물)

### 오픈 전에 합의할 것 (기능이 아니라 **약속**)
1. **공개 범위** — 자동 배포는 이제 기본 `unlisted`(링크 아는 사람만)로 나간다.
   전체공개 전환을 누가 언제 하는지 ENA 와 정해야 한다. "자동인데 왜 공개가 아니냐" 는
   반대로 "사람 안 거치고 공개된다" 보다 훨씬 나은 사고다.
2. **승인 정책** — 규칙마다 `approve_first`(사람이 먼저 푼다) / 자동 진행 중 택일.
   첫 2주는 `approve_first` 를 권한다. 승인 큐가 곧 품질 로그가 된다.
3. **하루 할당량** — 채널당 기본 3건. 아카이브 소진 속도와 채널 도배 사이의 손잡이다.
4. **누가 보는가** — ENA 담당자 계정은 자기 워크스페이스만 본다. 우리 운영자는 admin 으로
   같은 데이터를 보며 지원한다(첫 고객은 외주형 지원을 각오한 구조다).

## 4. AENA 가 안정적으로 부를 수 있는가 — 운영 관점

| 축 | 현재 | 오픈 전 조치 |
|---|---|---|
| 인증 | `x-api-key: stepd_live_…` (프록시 경유) 또는 Bearer(Cloud Run 직통) | ENA 에 **프록시 경유 + x-api-key** 로 안내. 키는 superadmin 콘솔에서 발급 |
| 화이트리스트 | 키로 열리는 라우트 22개 (나머지 전부 403) | 필요한 것만 열려 있는지 ENA 시나리오로 1회 관통 |
| 멱등 | `idempotencyKey` 지원하나 **DB 제약이 아니라 조회 후 생성** → 동시 2건이면 잡 2개 | AENA 쪽에서 회차당 직렬 호출로 회피(합의), 근본 수정은 오픈 후 |
| 레이트리밋 | ingest 시간당 20건/워크스페이스 | 아카이브 배치 속도와 맞는지 확인 후 조정 |
| 시작 지연 | 워커가 drain 모드 + Cloud Scheduler → **호출 직후 즉시 시작 아님** | ENA 에 "접수는 즉시, 처리 시작은 최대 N분" 으로 명시 |
| 실패 통지 | 없음(폴링만) | §2 의 상태 확장으로 대체. 웹훅은 오픈 후 |
| 모니터링 | 실패를 사람이 화면에서 봐야 앎 | 오픈 주에는 **우리가 매일 1회 /ops 와 자동화 로그를 본다**(사람 절차로 메움) |

## 6. 리스크 (계약 관점에서 아픈 순서)

1. **엉뚱한 영상이 공개로 나간다** — 이번에 `unlisted` 기본값으로 낮췄지만, 규칙 설정을
   사람이 `public` 으로 바꿀 수 있다. 첫 달은 규칙 변경을 우리가 같이 확인한다.
2. **아카이브 판권** — 게이트(rights)는 "미판정 = 통과" 다. 어떤 회차가 재배포 가능한지는
   **ENA 가 알려줘야 하는 정보**고, 우리 시스템이 판단하지 않는다. 계약서에 명시할 것.
3. **원가 초과** — 100편 ≈ ₩28,500(분석만). 선불 크레딧이 떨어지면 분석이 멈춘다(402).
   자동 충전은 지금 꺼져 있다 — ENA 는 수동 충전 + 잔액 알림으로 간다.
4. **사무실 PC 의존** — 유튜브 URL 투입(B안)과 네이버 발행은 윈도우2 전용이다.
   ENA 물량을 이 경로로 받으면 그 PC 가 곧 SPOF 다. A안(직접 업로드)을 기본으로.
