# 세로 AI 리프레임 비교 뷰어 및 자동선택 계획

> 2026-08-24 접수(사용자 계획서 원문 유지) + 같은 날 코드 대조 부록(§8) 추가.
> 1차 목표는 자동배포 연결이 아니라 **비교 뷰어 + 평가 데이터 구축**이다.

## 요약

가로 16:9는 기존 방식으로 유지하고, 세로 숏폼에만 AI 리프레임을 적용한다.
첫 단계는 자동배포 연결이 아니라, 한 영상의 주요 장면을 4개 세로 레이아웃으로 동시에
비교하는 내부 비교 뷰어다. 비교 결과를 사람이 평가한 뒤 선택 기준을 고정하고, 검증된
규칙만 자동배포에 연결한다.

## 1. 평가 코퍼스와 후보 생성

- 예능·드라마·인터뷰·다인 장면·와이드샷·빠른 카메라 이동·자막 밀집 장면을 포함한 대표 클립 20~30개를 선정한다.
- 기존 Beat, shot boundary, 얼굴 추적, 발화자, 자막 정보를 재사용한다.
- 장면별 후보는 다음 4개로 고정한다.
  - `9:16-letterbox`: 전체 담기
  - `9:16-crop-sub`: 위아래 띠
  - `9:16-crop-main`: 위 자막띠
  - `9:16-crop-full`: 꽉 채우기
- 가로 16:9는 후보에서 제외한다.
- 각 후보는 레이아웃, 크롭 영역, 추적 경로, 점수, 선택 이유를 함께 출력한다.
- 기존 Fit/Fill 결과는 각각 letterbox/crop-full 로 호환한다.

## 2. 레이아웃 선택 정책

각 후보는 먼저 안전성 검사를 통과해야 한다.

- 얼굴 감지율 75% 미만이면 탈락
- 주인공 우세도 60% 미만이면 공격적 크롭 탈락
- 크롭 안전률 80% 미만이면 해당 후보 탈락
- 0.5초 이상 추적 누락 또는 다인 모호 구간이 있으면 letterbox 우선
- 자막·타이틀·로고가 플랫폼 Safe Zone 과 겹치면 탈락

안전성 통과 후보 중 다음 점수로 최고 후보를 선택한다.

| 항목 | 가중치 |
|---|---|
| 주요 인물 보존 | 30 |
| 발화자 보존 | 20 |
| 자막·오버레이 안전 | 20 |
| 크롭 안전성 | 15 |
| 화면 활용률 | 10 |
| 추적 안정성 | 5 |

추가 규칙:

- 한 명의 발화자가 안정적으로 추적되면 crop-full 우선
- 한 명 중심이지만 상단 정보 영역이 필요하면 crop-main
- 다인·와이드 구도면 crop-sub
- 감지·추적·자막 판단이 불안하면 letterbox
- 레이아웃 전환은 샷 경계에서만 허용한다.
- 동일 레이아웃은 최소 2초 유지하고, 점수 차이가 10점 미만이면 기존 레이아웃을 유지한다.
- 안전성 악화 시에는 즉시 더 보수적인 레이아웃으로 강등한다.

Adobe 의 Semantic Subject Lock·추적 속도 제어, CapCut 의 장면별 재검토·자막 충돌 검사를
참고 기준으로 삼는다. [Adobe Reframe API](https://developer.adobe.com/audio-video-firefly-services/guides/reframe/) ·
[CapCut Auto Reframing Guide](https://www.capcut.com/create/capcut-auto-reframing-16-9-video)

## 3. 비교 뷰어

내부 전용 `/reframe-lab` 화면을 추가한다.

화면 구성: 원본 영상 · 대표 프레임 contact sheet · 4개 레이아웃 후보 프레임 ·
후보별 점수와 탈락 이유 · 샷별 레이아웃 타임라인 · 후보별 3~5초 짧은 프리뷰 재생 ·
얼굴 박스·추적 중심·자막 영역·Safe Zone 토글.

프레임 추출 위치: 시작·끝 · 25%·50%·75% · 모든 shot boundary · 레이아웃이 바뀌는 지점.

플랫폼 UI 가 텍스트와 로고를 가릴 수 있으므로 Safe Zone 표시를 기본 제공한다.
[Google vertical video safe zones](https://support.google.com/google-ads/answer/9128498?hl=en) ·
[TikTok Creative Codes](https://ads.tiktok.com/business/library/Creative_Codes_ENG.pdf)

## 4. 인터페이스와 데이터 흐름

비교용 결과는 정식 `clip.reframe` 상태와 분리한다.

- POST → 비교 작업 생성, 출력: 비교 작업 ID
- `GET /api/clips/:id/reframe/candidates/:jobId`
  - 상태, 후보별 plan, 프레임 contact sheet URL, 짧은 프리뷰 URL 반환
- 비교 결과는 임시 GCS 분석 경로에 저장한다.
- 사람이 승인한 후보만 정식 `clip.reframe` 플랜으로 채택한다.
- 기존 자동배포와 기존 `clip.reframe` API 의 동작은 비교 단계에서 변경하지 않는다.

## 5. 사람 평가와 기준 확정

각 후보를 1~5점으로 평가한다: 주인공 가시성 · 발화자/대화 상대 자연스러움 ·
얼굴·손·중요 객체 비절단 · 자막·제목 안전 · 화면 답답함 · 전환·카메라 이동 자연스러움.

초기에는 내부 편집자 2명이 평가한다.

채택 조건:

- 두 평가자의 1순위 일치율 70% 이상
- 얼굴·자막의 치명적 잘림 5% 이하
- 기존 중앙 크롭보다 사람이 선택한 결과가 우수
- 레이아웃 전환이 영상 1분당 평균 6회 이하

평가 결과는 레이아웃 선택 규칙과 가중치 조정의 근거로 보존한다.

## 6. 자동배포 연결

비교 코퍼스 기준을 통과한 뒤에만 자동배포에 연결한다.

- 자동배포 규칙에서 portrait + reframe: ai 인 경우에만 적용
- 가로 콘텐츠에는 기존 렌더 경로 유지
- AI 후보 생성 실패, 모델 실패, 시간 초과 시 기존 Fit/Fill 경로로 폴백
- 플랜이 없거나 안전성 검사를 통과하지 못하면 letterbox 로 폴백
- 자동배포 로그에 선택 레이아웃, 점수, 이유, 폴백 여부를 기록
- 기존 30분 정체 강등 안전벨트는 유지

## 7. 테스트 계획 · 기본 가정

- 레이아웃별 크롭 영역과 웹 미리보기·서버 렌더 결과 일치 테스트
- 단일 인물·다인·무얼굴·자막 밀집·추적 누락·샷 전환 fixture 테스트
- 후보 플랜의 시간 범위·추적 좌표·레이아웃 enum 검증
- 2초 미만 전환 방지·샷 경계 전환 테스트
- 기존 Fit/Fill 플랜의 동일 결과 변환 회귀 테스트
- 비교 작업 실패·재시도·임시 산출물 만료 테스트
- 자동배포에서 가로 콘텐츠가 AI 경로로 들어가지 않는지 테스트

기본 가정: 1차 목표는 비교 뷰어와 평가 데이터 구축 · 세로 4종은 기존 편집기 프리셋
그대로 · 새 모델 학습 없이 기존 분석 결과 + 결정론 정책 · 사람 승인 전에는 비교 결과가
실제 배포·정식 클립 상태를 바꾸지 않는다.

### 방향 전환 (2026-08-25 오후 · 사용자)

**beat 구간별 얼굴추적 크롭 평가는 접었다** — "어차피 저런 크롭 안 쓸 건데 뭘 평가하나.
편집기 레이아웃 중 어떤 걸 쓸지만 고르는 것." 렌더는 편집기 프리셋(aspect-presets 세로
4종 · 고정 기하)으로만 나가므로 평가 단위를 그에 맞췄다:

- 랩 화면 = **클립당 1클릭** — 세로 4종을 편집기 기하 그대로(정적·중앙 크롭) 나란히 보여
  주고 하나 고르면 저장 → 다음 미라벨 클립 자동 이동. AI 의 구간별 판단은 "AI 추천" 배지
  하나(타임라인 최장 레이아웃)로 접었다.
- 라벨 스키마는 그대로(reframe_labels) — 클립 단위 라벨은 beat_id NULL 로 구분.
- candidates.py 의 추적·히스테리시스 코드는 삭제하지 않는다 — 이후 "꽉 채우기 안에서의
  패닝"이 필요해지면 그때 되살린다. §2 의 게이트·점수는 "AI 추천" 계산에 계속 쓰인다.
- 이에 따라 §5 의 목표도 "구간 일치율"이 아니라 **클립 레이아웃 분류 정확도**(AI 추천 vs
  사람 선택)가 된다.

## 9. 운영 원칙과의 절충 — "Lab" 에 대해

리포 원칙은 "연구·통계·측정은 UI 로 만들지 않고 md 문서로, Lab 은 운영 워크플로만"
(구 STEP D Lab 2026-08-10 제거). 이 계획의 비교 뷰어는 사람이 **프레임·프리뷰를 눈으로
비교**해야 해서 md 로 대체가 안 되는 예외다. 절충:

- 뷰어는 **비교 재생 전용**(플랜 채택 = 운영 행위)으로 좁게 유지한다.
- **평가 점수·채택 기준 판정·가중치 조정 근거는 md 문서로 축적**한다
  (`docs/research/reframe-corpus-*.md`) — 측정 결과가 UI 에만 사는 상태를 만들지 않는다.
