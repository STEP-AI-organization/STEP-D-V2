# 토스쇼핑 쉐어링크 연동 계획

> 작성 2026-08-31 · **코드 없음 · 계획 단계.** 착수 조건은 §5.
> 쿠팡 파이프라인 정본은 [`docs/ops/commerce-links.md`](../../ops/commerce-links.md) —
> 이 문서는 **거기서 무엇이 그대로 쓰이고 무엇이 갈리는지** 만 다룬다.
> 외부 사실은 2026-08-31 토스 공식 문서 확인분이며 출처는 §7.

---

## 0. 한 줄

**같은 파이프라인에 채널 하나를 더 단다.** 새로 만들 것은 링크 발급부와 상품 매칭부뿐이고,
나머지(장면→상품 추출 · 사람 승인 · 발행 조립 · 회사별 계정 가드)는 쿠팡 것을 그대로 쓴다.

---

## 1. 왜 하는가

| | 쿠팡파트너스 | 토스쇼핑 쉐어링크 |
|---|---|---|
| 커미션 | 실효 **2% 미만** | **결제금액의 10%** |
| 전환 인정 | — | 클릭 후 **24시간** 내 결제 |
| 정산 | — | 매월 1일~말일 → **익월 25일** 지급 |
| 링크 발급 | **비공식** 콘솔 내부 API · 브라우저 필요 | **공식 Open API** · 서버 대 서버 |
| 운영 위치 | 윈도우2(한국 IP·화면 있는 크롬 필수) | **클라우드 가능** |

요율이 5배 이상이고, 발급이 공식 API 라 **윈도우2 의존이 사라진다.**
쿠팡은 "길이 열려 있어 먼저 관통한" 경로였고, 토스는 그 길 위에 얹는 첫 실수익 채널이다.

## 2. Open API 계약 (문서 확인분)

### 인증

- **승인제.** 신청 → 검수 → **승인받은 사업자(정산 거래처)만** 인증 정보를 받는다.
- 크리에이터 어드민의 API 연동 메뉴에서 신청 · 심사 **영업일 5일 이내**
- 발급물: **Access Key / Secret Key 한 쌍** → 이걸로 액세스 토큰을 받는다(Bearer)
- **출발지 IP 등록 최대 10개** (단일 IPv4 또는 /16~32 CIDR)
- 스코프 둘: `sharelink:read`(조회) · `sharelink:write`(발급)

> ⚠️ 토큰 발급 엔드포인트·만료 시간은 아직 안 읽었다("빠른 시작" 페이지에 있음).
> 키를 받은 뒤 확정한다.

### 링크 발급

```
POST https://sharelink.toss.im/openapi/links      (scope: sharelink:write)
body { publisherId, tacaItemId | tacaId }         ← 둘 중 최소 하나 필수
 →   { resultType, tacaItemId, publisherId, shortUrl, originUrl }
```

- 일부 상품은 **발급 제한**이 걸리고, 사유가 응답에 실려 온다 → 화면이 그 사유를 말해야 한다
- 문서 권고: **발급한 링크는 저장해 두고 재사용**한다 (호출 제한 명시는 없음)

### 조회 (scope `sharelink:read`)

카테고리 트리 · 카테고리 베스트 상품 · 하루특가 · 베스트 상품 · 상품 상세.

### ⚠️ 검색 API 가 없다 — 이 계획의 최대 변수

키워드로 상품을 찾는 API 가 **없다.** 우리 파이프라인은 `장면 → 검색어 → 검색 → 상품`
이라 이 축이 그대로는 안 맞는다.

또한 운영정책이 승인 **제외** 대상으로 "상품 데이터를 저장해 이커머스처럼 전시하거나
가격 비교하는 커머스형 웹사이트" 를 명시한다. 우리가 하려는 것은 전시가 아니라 **내부
매칭용 보관**이지만, **여기 걸리는지 심사에서 반드시 확인해야 한다.**

## 3. 설계 — 무엇이 그대로이고 무엇이 갈리나

| 단계 | 쿠팡 구현 | 토스 |
|---|---|---|
| 장면 → 상품 검색어 | 메타 생성 콜에 편승(추가 원가 ₩0) | **그대로** |
| 검색어 → 상품 확정 | 콘솔 검색 API → 결정론 규칙 | **새로 — §3.1** |
| 상품 → 제휴 링크 | 브라우저 컨텍스트에서 내부 API | **새로 — 서버에서 REST 1콜** |
| 발급 ≠ 게시 (전부 대기) | 있음 | **그대로** |
| 사람 승인 화면 `/commerce` | 있음 | **그대로** (채널 열만 추가) |
| 발행 직전 조립·대가성 문구 | 있음 | **그대로** |
| 회사별 계정 · 오귀속 가드 3중 | 있음 | **그대로** (자격증명 형태만 다름 — §3.2) |
| 자기 클릭 차단 | 있음 | **그대로 · 호스트 목록에 토스 단축 도메인 추가** |

### 3.1 검색이 없을 때 상품을 어떻게 고르나

세 갈래가 있고, **심사 답변에 따라 고른다.**

| 안 | 방법 | 조건 | 평가 |
|---|---|---|---|
| **A** | 카테고리 트리 + 베스트/하루특가를 주기적으로 받아 **내부 카탈로그**를 만들고, AI 가 뽑은 검색어를 거기에 매칭 | 상품 데이터 보관이 정책상 허용돼야 함 | 커버리지 최선 · **정책 확인 필수** |
| **B** | 카테고리만 매칭해 그 카테고리 **베스트 상위**를 건다 | 보관 없이 매 건 조회 | 정책 안전 · 상품 적합도 낮음 |
| **C** | 사람이 `/commerce` 에서 상품을 직접 지정하고 시스템은 발급만 | 없음 | 확실하지만 **사람 노동이 늘어난다** — 우리 원칙에 역행 |

기본안은 **A**, 정책이 막으면 **B**, 그래도 품질이 안 나오면 그때 C 를 부분 도입한다.
어느 안이든 **상품 선택은 결정론**을 유지한다 (AI 에게 순위·선별을 시키지 않는다).

### 3.2 회사별 계정

쿠팡은 정산이 계정 단위라 **회사마다 법인 계정 + 로그인 세션 주입**이었다.
토스는 발급 요청에 `publisherId`(발급 주체 식별자)가 들어가므로, **키 한 벌로 여러
퍼블리셔를 가를 수 있는지**가 갈림길이다.

- 가능하면 → 회사별 `publisherId` 만 저장하면 된다 (세션 봉인 구조가 필요 없어진다)
- 불가능하면 → 쿠팡처럼 **회사별 자격증명**을 봉인 저장한다 (기존 구조 재사용)

**심사 때 확인할 항목이다.** 어느 쪽이든 오귀속 가드 셋(격리 · 회사 대조 · **폴백 없음**)은
그대로 건다 — 계정을 잘못 고르는 실패는 에러가 아니라 "발급 성공" 으로 보이기 때문이다.

## 4. 지켜야 할 것

| # | 규칙 | 근거 |
|---|---|---|
| 1 | **경제적 이해관계 표시** — 상품 소개 근처에 쉽게 인식되게 | 운영정책 명시. 우리 구조는 발행 직전에 지울 수 없게 붙이므로 이미 만족 |
| 2 | **무효 클릭·자동 실행 금지** | 운영정책 명시. 발급 링크를 우리가 열지 않는 기존 규칙 그대로 + 차단 호스트에 토스 도메인 추가 |
| 3 | 발급 제한 사유를 사람에게 보인다 | 일부 상품은 발급이 막히고 사유가 온다 — 삼키면 "왜 안 붙었는지 모르는" 조용한 실패가 된다 |
| 4 | 발급 링크는 저장해 재사용 | 문서 권고 |

> 쿠팡 정책과 달리 **본인 클릭·본인 구매에 대한 명시 조항은 문서에서 못 찾았다.**
> 없다고 해서 해도 된다는 뜻이 아니므로, 쿠팡과 **같은 수준으로 막는다.**

## 5. 착수 조건 (게이트)

**아래 1~2 가 끝나기 전에는 코드를 쓰지 않는다.** 답에 따라 §3.1·§3.2 설계가 갈린다.

1. **Open API 사용 신청 → 승인** (심사 영업일 5일)
   - 승인 대상에 "SNS·블로그·웹사이트 및 **이들 채널의 게시 자동화 플랫폼**" 이 명시돼
     있어 우리 형태는 부합한다
2. **심사 과정에서 확인할 것 셋**
   - ① 상품 데이터를 **내부 매칭 용도로 보관**해도 되는가 (§3.1 A안의 전제)
   - ② 키 한 벌로 **여러 퍼블리셔(고객사)** 를 가를 수 있는가 (§3.2)
   - ③ 자동 발급의 허용 범위·호출 제한
3. **출발지 IP 고정** — 등록 상한 10개. 클라우드에서 부를 것이므로 고정 IP 경로가 필요하다
   (안 되면 기존 윈도우2 에서 도는 것으로 시작할 수 있다 — 쿠팡과 같은 자리라 추가 비용 0)

| 5 | 상품 매칭부 구현 (A/B 중 확정안) | 2 |

| 7 | 게이트 OFF 로 배포 → 실제 회차 한 바퀴 → ON | 6 |

**7 의 "실제 한 바퀴" 를 건너뛰지 않는다** — 쿠팡이 지금 그 자리에서 멈춰 있고,
그게 이 기능의 마지막 미확인 구간이다.
