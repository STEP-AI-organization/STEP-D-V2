# NATIVE 관리형 작업 공간 — 설계

> 상태: **1~3단계 구현 완료 · 미배포** (2026-09-07) · 4단계부터 미착수
> 대상: `native/` · `apps/server/src/index.ts` · `admin/` · `packages/premiere`
> 관련: [native/CLAUDE.md](../../../native/CLAUDE.md) · [docs/ops/infra.md](../../ops/infra.md)

## 무엇을 바꾸려는가

지금 NATIVE 는 **편집자가 고른 아무 경로의 파일**을 업로드한다. 다운로드 폴더든 바탕화면이든
외장 디스크든 상관하지 않는다. 바꾸려는 것은 이것 하나다 —

> **파일은 STEP-D 가 정한 작업 공간 안에서만 산다.** 밖의 파일은 복사해 들여온 뒤에 다룬다.

얻는 것: 회차별로 원본·프록시·프로젝트·완성본이 한자리에 모이고, 프리미어 렌더 결과가
어디로 갔는지 찾을 필요가 없어지며, "그 파일 어디 있죠" 가 사라진다.

치르는 것: **디스크가 두 배로 든다**(원본을 복사하고 원본은 남긴다 · 60분 원본이 수 GB).
그리고 네이티브를 고치므로 **편집자 PC 마다 사람이 다시 깐다**(자동 업데이트 없음).

## 지금 코드가 실제로 어떻게 생겼나

설계를 실물 위에 얹기 위해 먼저 적는다. (2026-09-07 실측)

```
native/src/
  contract.ts     웹과의 계약 — version: 1 · enqueueUpload/list/pause/... 9개
  preload.ts      신뢰 origin 에서만 브리지 노출 · webUtils.getPathForFile 로 경로 추출
  main.ts         창·트레이·stepd:// · IPC 핸들러
  transfer/
    engine.ts       enqueue(filePath, request) → 청크 업로드 · 308 재개
    job-store.ts    작업 영속화 (userData/transfer-queue · DPAPI 로 봉인)
    validation.ts   validateVideoPath — 절대경로 · 확장자만 본다 (26줄)
    fingerprint.ts  같은 크기로 바꿔치기된 파일 탐지
```

**중요한 사실 셋:**

1. **경로는 렌더러가 만든다.** `preload.ts` 가 `webUtils.getPathForFile(file)` 로 뽑아
   IPC 로 넘긴다. 즉 지금 구조에서 경로 문자열은 **웹 쪽에서 시작된다.**
2. **검증은 `validation.ts` 26줄이 전부다.** 절대경로인지, 지원 확장자인지만 본다.
   루트 대조도 realpath 도 없다.
3. **작업 큐는 절대경로를 저장한다**(`StoredUploadJob.filePath`). 파일이 움직이면
   `FILE_MISSING`·`FILE_CHANGED` 로 떨어지고 사람이 다시 고른다(`relinkUpload`).

## 설계

### 1. 경로 두 갈래 — 앱과 콘텐츠를 가른다

```
앱          %LOCALAPPDATA%\Programs\@stepdnative\STEP-D.exe   (지금 그대로)
설정·세션    %USERPROFILE%\.stepd\                             (신규)
콘텐츠       %USERPROFILE%\STEP-D Workspace\                   (신규 · 정책으로 변경 가능)
```

⚠️ **작업 큐(`userData/transfer-queue`)는 옮기지 않는다.** DPAPI 로 봉인돼 있고 사용자
프로필에 묶이는 게 맞다. 콘텐츠만 옮긴다.

### 2. 표준 폴더

```
STEP-D Workspace/
└─ {프로그램}/
   └─ {회차}/
      ├─ source/     원본 (업로드 대상)
      ├─ proxy/      프록시·저해상도
      ├─ project/    프리미어 프로젝트
      ├─ export/     프리미어 렌더 결과
      └─ delivery/   납품본
```

폴더명·구조는 **정책 버전**을 달고 서버가 준다. 앱이 상수로 들고 있으면 회사마다 다르게
못 하고, 바꾸려면 전원 재설치다.

### 3. 신뢰 경계 — **여기가 이 설계의 핵심이다**

계획 초안은 `enqueueUpload` 안에서 "관리형 경로인지 검사" 하자고 했다. **그 자리가 틀렸다.**

`preload.ts` 는 렌더러(웹) 문맥에서 돌고, 웹은 우리가 서명한 코드가 아니라 **브라우저 안
JS** 다. 브리지 진입점의 검사는 우회가 아니라 그냥 "다른 IPC 호출 한 줄"로 뚫린다.

```
❌ preload 에서 검사        → 렌더러가 ipcRenderer.invoke 를 직접 부르면 끝
✅ 메인 프로세스에서 검사   → fs 를 만지기 직전. 렌더러가 우회할 수 없는 유일한 자리
```

**규칙:** 경로 판정은 전부 `main.ts` 의 IPC 핸들러 뒤(`validation.ts` 확장)에서 한다.
`preload.ts` 는 경로를 **전달만** 하고 아무것도 판단하지 않는다.

더 나아가려면: 렌더러에 경로 문자열을 주지 않고 **핸들(불투명 id)** 만 주는 방향이 있다.
이번 범위 밖으로 두되, 계약을 바꿀 때 그 방향을 막지 않게 설계한다.

### 4. 경로 탈출 차단 — 심볼릭 링크만으로는 부족하다

Windows 에서 루트 밖을 가리키는 길은 심볼릭 링크만이 아니다.

| 우회 | 예 |
|---|---|
| 정션(junction) | `mklink /J` — 심링크와 다른 타입이다 |
| 하드링크 | 파일 자체가 두 경로에 존재 |
| `\\?\` 접두사 | `\\?\C:\...` — 정규화를 건너뛴다 |
| 8.3 단축명 | `C:\PROGRA~1\...` |
| UNC | `\\server\share\...` |
| 대소문자·후행 공백/점 | `C:\Users\...` vs `c:\users\...` · `name ` |

**판정은 `fs.realpath` 로 정규화한 뒤 루트와 대조한다.** `path.resolve` 비교로는 못 잡는다.

```
realpath(대상)  이   realpath(작업공간루트)  의 하위인가
  · 대소문자 무시 비교(Windows)
  · 경계는 구분자까지 본다 — "C:\WS-evil" 이 "C:\WS" 의 하위로 읽히면 안 된다
```

⚠️ **TOCTOU 가 남는다.** 검사 통과 후 링크로 바꿔치기하면 뚫린다. 완전한 해법은 열어 둔
파일 핸들로만 다루는 것이지만, 업로드 엔진이 경로를 여러 번 다시 여는 구조라 이번엔
**검사 시점을 열기 직전으로 좁히는 것**까지만 한다. 남는 구멍은 문서에 적어 둔다.

### 5. 들여오기(import) — 원자성

```
1. 대상 폴더 결정 (정책 + 프로그램/회차/폴더)
2. 같은 볼륨의 임시 파일로 복사   ← ⚠️ 같은 볼륨이어야 한다
3. 지문 계산·대조
4. rename 으로 정식 이름 부여     ← 같은 볼륨에서만 원자적
```

⚠️ **임시 파일을 `%TEMP%` 에 두면 안 된다.** 작업 공간이 다른 드라이브면 `rename` 이
복사로 바뀌어 원자성이 깨지고, 완료 기준("불완전한 정식 파일이 남지 않는다")을 못 지킨다.
임시 파일은 **대상 폴더 안**(`.stepd-tmp/`)에 만든다.

실패·강제종료 시 남은 임시 파일은 다음 기동에 정리한다(이름 규칙으로 식별).

### 6. 파일명·경로 길이 — 계획에 없던 것

- **경로 길이 260자.** `STEP-D Workspace\프로그램명\회차명\source\파일명` 은 한글 이름이면
  금방 넘긴다. 긴 경로 옵션이 꺼진 PC 가 많다 → **폴더명 길이를 잘라 쓰고**, 넘치면
  사람이 읽을 수 있는 오류로 거절한다(조용히 실패하지 않는다).
- **한글 정규화(NFC/NFD).** macOS 를 거친 파일명은 자모가 분리돼 온다 → 저장 전에 NFC 로.
- **금지 문자·예약어.** `\ / : * ? " < > |` · `CON` `PRN` `AUX` `NUL` `COM1..9` `LPT1..9` ·
  후행 공백·점.
- **디스크 여유.** 복사 전에 확인한다. 원본 크기 + 여유. 부족하면 **복사를 시작하지 않는다** —
  중간에 실패하면 임시 파일과 시간을 함께 버린다.

### 7. 정책 — 서버가 준다

```
GET   /api/native/policy                        (세션 · 자기 회사 것)
PATCH /api/superadmin/tenants/:id/native-policy (운영자 · 사유 필수)
```

응답에 담기는 것: 정책 버전 · 작업 공간 루트 규칙(또는 템플릿) · 표준 폴더 이름 ·
허용 확장자 · 외부 파일 자동 복사 여부 · 구조 버전 · 활성 여부.

⚠️ **정책을 못 받아도 일은 계속돼야 한다.** 초안은 "정책을 받지 못하면 새 파일 등록 보류"
라고 했는데, 지금 업로드 큐는 **오프라인에서도 도는 게 설계**다(창을 닫아도 앱을 껐다 켜도
이어받는다). 서버가 잠깐 죽었다고 현장 편집자가 아무것도 못 올리면 그건 기능이 아니라 사고다.

```
정책 있음        → 그대로
정책 조회 실패   → **마지막으로 받은 정책을 캐시에서 쓴다** (.stepd/policy.json)
캐시도 없음      → 그때만 보류하고, 왜 보류인지 화면에 적는다
```

### 8. 기존 큐 — 데이터를 버리지 않는다

이미 큐에 있는 외부 경로 작업은 **자동으로 옮기지도 지우지도 않는다.**

```
기존 작업 → needs_attention (이미 있는 상태다 · 새 상태를 안 만든다)
          → "작업 공간으로 가져오기" 를 사람이 누르면 복사 후 재연결
새 작업   → 관리형 경로가 아니면 거부 (importToWorkspace 를 먼저 거치게)
```

`needs_attention` 은 `contract.ts` 에 이미 있는 상태다. 새 상태를 만들면 웹의 상태 표시가
전부 갈라진다 — 있는 것을 쓴다.

## 계약 변경 — 배포 순서가 걸린다

`contract.ts` 에 메서드를 **추가**한다. `native/CLAUDE.md` 의 규칙 그대로:

> 계약에 메서드를 추가 → **앱을 먼저 깔고, 그 다음 웹에서 쓴다.** 순서를 뒤집으면 아직 안
> 깐 PC 에서 `bridge.newMethod is not a function` 이 난다(버전 가드는 숫자만 본다).

```ts
getWorkspaceInfo(): Promise<{
  rootPath: string; ready: boolean; policyVersion: number; folders: string[];
}>;

importToWorkspace(file: File, target: {
  programId: string; episodeId?: string;
  folder: "source" | "proxy" | "project" | "export" | "delivery";
}): Promise<{ managedPath: string; filename: string; size: number }>;
```

`version` 은 **올리지 않는다.** 올리면 앱을 안 깐 PC 가 전부 브라우저 업로드로 떨어져
네이티브 이점이 통째로 사라진다. 웹은 `typeof bridge.getWorkspaceInfo === "function"` 으로
기능 유무를 보고 없으면 지금 동작을 그대로 쓴다.

## 단계

각 단계는 **그 자체로 배포 가능**해야 한다. 중간 상태에서 편집자가 일을 못 하면 안 된다.

| # | 무엇 | 배포 대상 | 사람이 체감하는 변화 |
|---|---|---|---|
| 1 | ✅ 관리형 루트 계산 · 표준 폴더 생성 · `getWorkspaceInfo` | 앱 | 없음(폴더만 생김) |
| 2 | ✅ 경로 탈출 차단 · 들여오기(복사·지문·원자성) · `importToWorkspace` | 앱 | 없음(웹이 아직 안 부름) |
| 3 | ✅ 웹 업로드를 들여오기 경유로 | 웹 | 외부 파일이 복사된 뒤 올라간다 |
| 4 | 정책 API + 어드민 설정 | 서버·어드민·앱 | 회사별 규칙이 먹는다 |
| 5 | 프리미어 렌더 → `export/` | 프리미어 플러그인 | 렌더 결과를 찾을 필요가 없다 |
| 6 | 다운로드·프록시·프로젝트 파일 관리 | 웹·앱 | 받은 파일이 회차 폴더로 |
| 7 | 폴더 감시·자동 등록 | 앱 | 넣어 두면 올라간다 |
| 8 | 보관·정리 정책 | 앱·서버 | 디스크가 안 찬다 |

**1~3 을 한 덩어리로 보는 것을 권한다.** 3까지 가야 사용자에게 의미가 생기고, 1·2만
나가면 아무것도 안 바뀐 앱을 전원 재설치시키는 셈이다(자동 업데이트가 없다).

## 완료 기준 (테스트로 고정할 것)

순수 함수로 검증 가능한 것과 아닌 것을 갈라 둔다 — 이 리포 규칙이다.

**순수(단위 테스트):**
- 경로가 루트 하위인가 판정 — 대소문자·후행구분자·`C:\WS-evil` 같은 접두사 함정
- 파일명 정규화 — NFC · 금지문자 · 예약어 · 길이
- 정책 → 경로 해석 (프로그램/회차/폴더 → 절대경로)

**통합(실제 fs 필요):**
- 심볼릭 링크·정션이 루트 밖을 가리키면 거절
- 복사 중 강제 종료 → 정식 이름 파일이 **안 남는다**
- 같은 파일 재-들여오기 → 지문으로 중복 방지
- 다른 볼륨 작업 공간에서도 원자성 유지
- 디스크 부족 → 복사를 **시작하지 않는다**

**회귀:**
- 기존 외부 경로 큐 작업이 데이터 손실 없이 재연결된다
- 정책 조회 실패 시 캐시로 계속 돈다
- 앱이 구버전인 웹(`getWorkspaceInfo` 없음)에서도 업로드가 된다

## 남는 위험 — 적어 두고 간다

1. **TOCTOU** — 검사와 열기 사이의 바꿔치기. 이번 범위에서 완전히는 못 막는다.
2. **디스크 두 배** — 원본 유지가 전제다. 8단계(정리 정책)까지 가야 해소된다.
3. **작업 공간 이동** — 사용자가 폴더를 옮기면 큐의 절대경로가 죽는다. 재연결 흐름이
   이미 있으므로 거기에 얹되, 대량으로 깨질 수 있다.
4. **전원 재설치** — 자동 업데이트가 없다. 1~3 을 묶는 이유가 이것이다.

## 이번 범위 밖

- NAS·다중 저장소 (1차 안정화 뒤)
- 렌더러에 경로 대신 핸들만 주는 계약 개편
- macOS (지금 `platform: "win32"` 고정)

## 구현 메모 (1~3단계 · 2026-09-07)

```
native/src/workspace/policy.ts    순수 판정 — 이름 정규화 · 경로 해석 · 루트 안인가
native/src/workspace/manager.ts   배선 — realpath · 복사 · 지문 · 임시파일 청소
native/src/main.ts                assertManagedPath() ← **신뢰 경계는 여기 하나뿐**
native/src/preload.ts             경로를 전달만 한다(판단 없음)
apps/web/src/lib/native-transfers.tsx   enqueueUpload 안에서 들여오기를 먼저 부른다
```

**설계대로 지킨 것:**
- 판정은 `main.ts` 의 `assertManagedPath` 하나뿐이다. `enqueueUpload` 와 **`relink` 둘 다**
  통과한다 — relink 를 빼면 "다시 선택" 으로 밖의 파일을 밀어넣을 수 있다.
- 임시 파일은 대상 폴더 안 `.stepd-tmp/` 에 만든다(다른 드라이브에서도 rename 이 원자적).
- 계약 `version` 은 1 그대로. 웹이 `typeof bridge.importToWorkspace === "function"` 으로 본다.
