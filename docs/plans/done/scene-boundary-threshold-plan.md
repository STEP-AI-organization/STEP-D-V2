# 장면 경계 임계값 상향 및 과검출 억제 계획

작성일: 2026-07-30  
대상: `core/boundaries.py`, `core/beats.py`, `core/analyze.py`

## 목표

같은 화면 안에서 대화 주제만 바뀌는 구간까지 장면 전환으로 잡아내는 문제를 줄인다.
핵심은 **모델을 다시 만드는 것**이 아니라, 지금 있는 GEBD 경계 출력을 **더 보수적으로 채택**하도록 바꾸는 것이다.

## 전제

- GEBD/TSN 계열 결과는 “경계 후보”로만 사용한다.
- 최종 beat 경계는 모델 점수 1개로 결정하지 않는다.
- 더미 데이터나 합성 데이터는 쓰지 않는다.
- 지금 당장 가능한 현실적 조정만 한다.

## 설계 원칙

1. **모델 출력은 후보**
   - 경계 점수가 높아도 바로 beat로 쓰지 않는다.
   - transcript, speaker continuity, shot 변화, 최소 길이 조건을 같이 본다.

2. **과검출 비용을 더 크게 둔다**
   - 경계 하나를 놓치는 것보다, 한 문단/한 장면을 과하게 쪼개는 비용이 더 크다.
   - 특히 같은 화면에서 주제만 바뀌는 경우는 과검출로 간주한다.

3. **단계별 차단**
   - 낮은 점수 경계는 초기에 제거
   - 남은 경계는 후처리에서 병합
   - 그래도 남는 경계만 beat로 승격

## 실행 계획

### 1. 경계 후보 임계값 상향

- `core/boundaries.py`에서 boundary score 필터를 더 보수적으로 설정한다.
- 낮은 점수 경계는 로드 단계에서 제거한다.
- 중복 경계 병합 시에도 더 넓은 gap을 둔다.

### 2. beat 최소 단위 강화

- `core/beats.py`의 beat 생성에서 최소 beat 길이를 더 엄격하게 적용한다.
- 너무 짧은 경계 간격은 자동 병합한다.
- 동일 화자 연속 발화가 이어지면 경계 점수가 있어도 분할하지 않는다.

### 3. STT 기반 후처리 추가

- 문장/발화 간 간격이 짧으면 경계 후보를 약하게 본다.
- 자막이 연속되고 의미 단위가 끊기지 않으면 split을 억제한다.
- 장면 전환보다 발화 흐름이 더 강한 구간은 beat 유지 우선으로 처리한다.

### 4. shot/scene 보조 신호 활용

- shot 변화가 약한데 경계 점수만 높은 경우는 soft boundary로 둔다.
- `scene_type` 결과가 interview/on_scene처럼 안정적인 구간이면 더 보수적으로 본다.
- 시각 변화가 약하고 대화만 바뀌는 구간은 split 기준을 높인다.

### 5. 경계 등급화

- `hard`: 거의 확실한 장면 전환
- `soft`: 후보 경계
- `noise`: 무시

이렇게 나누고, beat 생성은 `hard` 위주로 시작한다.
`soft`는 transcript와 shot 조건을 만족할 때만 승격한다.

### 6. 검증 셋 구성

- 실제 방송/대화 영상 몇 개를 골라 수동 확인한다.
- 다음 케이스를 따로 본다.
  - 같은 화면에서 주제만 바뀜
  - 화면도 바뀌고 주제도 바뀜
  - 리액션 컷, 짧은 끼어듦, 재탕 컷
  - 긴 단일 대화 구간

### 7. 평가 지표

- 경계 과검출 수
- beat 평균 길이
- 짧은 beat 비율
- 사람이 거절한 경계 비율
- 추천 보드에서 실제 채택되는 beat 비율

## 우선순위

1. boundary score threshold 상향
2. min gap / min beat 길이 상향
3. transcript continuity gate 추가
4. shot/scene 보조 신호 연결
5. 검증 셋으로 재조정

## 완료 기준

- 같은 화면 대화 전환에서 불필요한 경계가 눈에 띄게 줄어든다.
- 짧게 쪼개진 beat가 줄고, 추천/편집 단위가 더 자연스러워진다.
- 사람 검수에서 “너무 잘게 쪼갠다”는 피드백이 줄어든다.
