데이터 흐름 — 영상 하나의 여정

업로드
브라우저 → GCS resumable로 직접(대용량·수 GB). 청크 재시도·지수 백오프로 끊겨도 재개.
분석 큐잉
서버가 content.analyze를 job_queue에 넣는다. Cloud Run은 큐잉만 한다.
AI 분석 (content 워커)
STT(Soniox) → 장면 분할 → GEBD GPU VM 경계 → beat 생성 → 장면 이해(Vision) → 쇼츠 추천 → 검색 인덱싱. 단계별 체크포인트로 실패 시 재개.
저장
content_analysis + search_segments(pgvector) 저장. 산출물은 GCS에 영구 보존.
채택 (사람)
운영자가 추천 구간을 채택/거절. 채택이 곧 클립이 된다. 평가·판단은 사람 몫.
렌더 (stepd-render)
전용 서비스에서 ffmpeg 트림·리프레임(9:16)·자막 번인. 편집 결정(editorState)을 결과물로 굽는다.
배포 & 성과
YouTube·Meta·TikTok·네이버로 발행 + 성과 추적. 자동배포: 규칙 → 승인 대기 → 승인/거부 → 게시(사람이 확정).

설계 원칙 & 비용

비용 구조

워커는 큐 비면 종료(drain), 서비스는 min 0. 유휴 과금을 없앤다. 고정비 ≈ ₩86,500/월 · 60분 회차 ≈ ₩800(마진 ~51%). 화면자막(chyron) 켜면 ≈ ₩1,240(마진 ~21% · 인물 검색축).

일의 분담

클라우드 = 무거운 분석·렌더·저장. 윈도우2 = 한국 IP가 필요한 네이버·다운로드. GPU는 GEBD만.

사람 vs 자동

"전부 자동"이 아니라 "사람 부담 최소화". 채택·승인·성공 판정은 사람이, 나머지는 파이프라인이 맡는다.

안전 기본값

실업로드 게이트는 기본 OFF, 발행은 단일 관문 + 테넌트 RLS. 실패의 방향이 "안 나감"이 되게 잡아둔다.
