1. 개요 · Base URL · 버전

STEP-D 외부 API는 고객사 시스템이 자사 영상을 넣고, AI 분석·쇼츠·배포 결과를 가져가기 위한 REST 인터페이스입니다. 사람이 쓰는 관리 화면(stepd.stepai.kr)과 결제·관리 라우트는 이 API에 포함되지 않습니다 — 화이트리스트에 명시된 경로만 열립니다.

Base URLhttps://<stepd-server>.us-central1.run.app  (또는 지정 커스텀 도메인)
프로토콜HTTPS 전용 · JSON (요청·응답 application/json, 업로드는 바이너리 PUT)
버전경로 무버전(v1 암묵). 파괴적 변경 시 사전 공지 + 병행 기간 제공
문자 인코딩UTF-8
시간 형식ISO-8601 (UTC) · 영상 내 시각은 초(seconds, float)
배포 전제조건 (중요). 현재 서버(Cloud Run)는 IAM 비공개이며 invoker가 domain:stepai.kr + 배포 SA로 한정되어, 외부 고객사가 서버 URL에 직접 붙으면 앱 인증 이전에 IAM에서 403이 납니다. 즉 API 키 인증 코드는 완비돼 있으나 외부 공개 인그레스가 아직 없습니다. 고객사 오픈 전 (a) 전용 공개 도메인/게이트웨이 또는 (b) allUsers invoker + 앱 레벨 키 인증 단독 중 하나를 운영과 확정해야 합니다.
격리 원칙. API 키 경로도 세션과 동일하게 app.tenant_id를 세워 PostgreSQL RLS로 워크스페이스 격리를 강제합니다. 키는 "누구 것인가"만 정하고 이후 경로는 화면과 동일합니다.

2. 인증 (API 키)

모든 요청은 워크스페이스 API 키를 Authorization 헤더에 Bearer 토큰으로 실어 보냅니다.

Authorization: Bearer stepd_live_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX

2.1 키 형식

구분접두용도
운영(live)stepd_live_실제 크레딧이 차감되는 운영 트래픽
테스트(test)stepd_test_연동 개발·검증용

키 본문은 24바이트 난수의 base64url 인코딩입니다. 예: stepd_live_ab12CD… (총 길이 가변, 표시·조회용 접두는 앞 15자).

2.2 저장 · 노출 규칙

  • 서버는 키 평문을 저장하지 않습니다. DB에는 sha256 해시와 접두 15자만 보관합니다.
  • 평문은 발급 응답에 딱 한 번 반환됩니다. 분실 시 재발급(회전)만 가능하며 복구는 불가합니다.
  • 키는 그 자체로 남의 채널에 영상을 올릴 수 있는 권한이므로, 고객사 서버 환경변수/비밀관리에만 보관하고 브라우저·클라이언트에 노출하지 마십시오.

2.3 거부 사유 (401/403)

상황결과
키 형식이 아님 / 헤더 없음401 · 인증 실패
알 수 없는 키 (해시 미일치)401 · "알 수 없는 API 키입니다."
폐기(revoke)된 키401 · "폐기된 API 키입니다."
워크스페이스(회사) 정지 상태403 · "워크스페이스가 정지되었습니다."
스코프 없는 키403 · "이 키에 허용된 권한이 없습니다."
화이트리스트 밖 경로 호출403 · "API 키로 호출할 수 없는 경로입니다."
경로는 열렸으나 스코프 부족403 · "이 키에 {scope} 권한이 없습니다."
두 가지를 구분합니다. "경로가 API에 없음"과 "키 권한 부족"은 다른 메시지로 응답합니다 — 연동 시 "우리 키가 잘못됐나"와 "그 기능은 API에 없나"를 구분할 수 있습니다.

3. 권한 스코프

키에는 하나 이상의 스코프가 부여됩니다. 각 엔드포인트는 필요한 스코프를 요구하며, 스코프가 없으면 403입니다. 최소 권한 원칙에 따라 필요한 스코프만 발급받으십시오.

스코프허용 동작
media:write미디어 업로드 개시·확정, 분석 큐잉
media:read분석 결과·자막·스트림 URL·쇼츠·클립·썸네일·프레임·세그먼트 조회
search:read영상 DB 하이브리드 검색
factory:write팩토리 파이프라인 개시(비디오/인제스트), 배포 채널 등록
factory:read팩토리 잡 상태·배포 타깃·성과 조회
billing:read크레딧 잔액·사용 내역 조회 (결제·카드는 API 불가, 화면 전용)
결제·관리·채널 OAuth는 API로 열리지 않습니다. 카드 등록·충전·회사/사용자 관리처럼 사람이 판단해야 하는 동작은 관리 화면 전용입니다.

4. 오류 응답 규격

오류 응답은 JSON입니다. 사람이 읽을 안정 필드는 message이며, error는 라우트에 따라 기계용 코드(예 insufficient_credits)이거나 서술 문자열(예 media not found)일 수 있습니다. 분기는 HTTP 상태 + error 코드값으로, 표시는 message로 하십시오.

// 코드형 (신규 라우트)
{ "error": "insufficient_credits", "message": "크레딧이 부족합니다." }

// 서술형 (구 라우트) — message 없이 error 만 오기도 함
{ "error": "media not found" }

// 인증/권한 (API 키 거부) — 전역 핸들러 경유
{ "error": "request_failed", "message": "폐기된 API 키입니다." }
방어적 파싱. 일부 응답은 message가 없습니다(예 {"error":"media_not_found"}). 연동 코드는 message ?? error ?? "HTTP " + status 순으로 읽으십시오. (규격 통일은 로드맵)

5. 크레딧 · 사용량 · 레이트

선불 크레딧 모델입니다(구독 없음). 크레딧 1개 = 분석 1분이며 회차 길이를 분 단위 올림으로 청구합니다.

단위1 크레딧 = 분석 1분 (ceil(재생초 / 60))
충전API 불가 — 카드/빌링키 결제는 화면 전용. 잔액·내역만 GET /api/credits
사전 게이트분석·팩토리 큐잉 전 잔액 확인 → 부족 시 402 insufficient_credits
차감 시점분석 완료 후 워커가 실제 길이로 차감 (reason:"usage")
멱등원장 dedupe_key 유니크 → 중복 차감 없음. 잔액 = 원장 합계(캐시 없음)
재분석사람이 재요청한 재분석은 attempt 키로 별건 청구
길이를 알 수 없을 때(초=0)는 사전 게이트가 막지 않고 완료 후 실제 길이로 차감합니다. 이미 소비된 비용은 실재하므로 잔액이 음수가 될 수 있습니다.

레이트 리밋

전역 레이트 리밋은 없습니다. 팩토리에만: 시간당 개시 상한 FACTORY_HOURLY_LIMIT(기본 20 → 초과 429), 일일 발행 상한(기본 5). 프레임/세그먼트 추출은 서버 내부 동시성 2로 제한됩니다(테넌트별 아님).

6. 업로드 흐름 (resumable)

대용량 원본은 브라우저·서버에서 GCS로 직접 resumable 업로드합니다(서버 바디를 경유하지 않음).

1) POST /api/media/upload-init          → { mediaId, objectPath, sessionUrl }
2) PUT  <sessionUrl>  (바이트 직접 업로드 · GCS resumable 프로토콜)
3) POST /api/media/finalize   { mediaId, objectPath }      → 202 { media, episode, queued:true }
4) 선택: POST /api/factory/ingest { sourceUrl: media.id, ... } → 202 { jobId }
5) 폴링 GET /api/media/<mediaId>/analysis  → status: none | pending | done | failed
objectPath는 uploads/<mediaId>.<ext> 형식이어야 하고 finalize는 GCS 모드 전용입니다. finalize 뒤 서울 스테이징→운영 버킷 이동·probe·분석은 media.prepare 워커가 자동 수행합니다. AENA는 완료를 기다리지 않고 factory ingest를 호출해도 되며, 공장 잡은 원본 준비가 끝날 때까지 ingesting에서 기다립니다. 소용량 멀티파트 POST /api/media/upload(~32MB Cloud Run 상한)는 키 화이트리스트에 없습니다(세션 전용).

7. 엔드포인트 레퍼런스

아래 22개가 API 키로 호출 가능한 전부입니다(화이트리스트). 목록 밖 경로는 무조건 403. 모든 경로는 /api/… 직하(버전 프리픽스 없음)이며 RLS 워크스페이스 스코프 안에서 실행됩니다.

7.1 미디어 (Media)

POST /api/media/upload-init media:write

resumable 직접 업로드 세션을 개시한다.

본문 필드타입설명
programIdstring선택 · 기본 "p1"
episodeNumbernumber선택 · 회차(중복 사전검사)
filename / contentTypestring선택 · 기본 "video.mp4" / "video/mp4"
200 → { "mode":"resumable", "mediaId":"...", "objectPath":"uploads/<id>.mp4", "sessionUrl":"https://storage.googleapis.com/..." }

400 program not found · 409 duplicate episode {episodeNumber,programId} · 500 failed to init upload · 비용 없음

POST /api/media/finalize media:write

바이트가 서울 GCS 스테이징에 안착한 뒤 회차·미디어를 등록하고 비동기 후처리를 큐잉한다. 재호출 멱등.

본문 필드타입설명

objectPathstring필수 · uploads/<mediaId>.<ext>
programIdstring기본 "p1"
title, filename, contentTypestring선택
episodeNumbernumber선택
broadDatestring선택 · YYYY-MM-DD
trackstring선택 · "variety" | "drama"
hasSubtitle, fastboolean선택
202 → { "media": {...}, "episode": {...}, "recommendations": [], "queued": true }

400 objectPath 형식/불일치·program not found·upload not found · 409 duplicate episode

POST /api/media/:id/analyze media:write

AI 콘텐츠 파이프라인을 큐잉(또는 재큐잉)한다. 큐잉 전 크레딧 게이트.

본문: { "fast"?: boolean }
200 → { "ok": true, "queued": true }      // queued:false = 이미 진행 중(멱등 성공)
402 → { "error":"insufficient_credits", "message":"..." }

200 → { "mediaId", "source":"transcript|content_analysis", "updatedAt", "segments":[...] }

7.2 검색 (Search)

GET /api/search search:read

하이브리드(벡터+키워드) 세그먼트 검색 — 제품의 핵심 질의. Vertex 임베딩 실패 시 키워드 단독 폴백(비오류).

쿼리 파라미터설명
q자연어 질의(빈값 → 하이라이트순 기본 목록)
program, episode프로그램·회차 필터
character인물(쉼표 구분)
is_shorttrue|1 → 쇼츠 후보만
genre, scene_type장르·장면유형
aired_from, aired_to방영일 범위
allow_spoilertrue → 스포일러 포함
top_k기본 20 (q 빈값 시 30)
200 → { "query","queryId","parsed":{...},"embedded":bool,"count",
        "results":[{ "segmentId","mediaId","start","end","duration","characters",
                     "sceneType","isShort","highlightScore","summary","dialogue",
                     "rightsStatus","score","lex","vec" }] }
500 → { "error":"...", "results":[] }

rightsStatus는 참고용 한국어 라벨(권리 판정 아님) · 비용 없음

7.3 팩토리 (Factory) — 소스 1건 → 분석·쇼츠·클립·발행 완주

본문: { "url": "<youtube>", "programId": "...", "title"?: "..." }

전자동 파이프라인 실행(즉시 반환). 킬스위치 FACTORY_ENABLED 꺼지면 503.

8.2 키 관리

API 키는 STEPAI 운영자만 관리 콘솔(superadmin 세션)에서 발급합니다 — 고객사는 별도 경로로 키를 전달받으며 셀프 발급 엔드포인트는 없습니다.

동작경로 (운영자 전용)
발급POST /api/superadmin/tenants/:id/api-keys → {id, key, prefix, scopes}
목록GET /api/superadmin/tenants/:id/api-keys (평문 없음)
폐기·회전POST /api/superadmin/api-keys/:keyId/revoke (soft-delete)

발급 응답의 key(평문)는 한 번만 반환됩니다. 분실 시 폐기 후 재발급. 스코프 미지정 발급 시 6개 전부 부여되므로 최소권한 위배 — 명시 발급을 권장합니다.

8.3 용어

워크스페이스고객사 격리 단위(내부 tenant). 키 1개 = 워크스페이스 1개.
미디어(media)업로드한 원본 롱폼 영상 1건.
쇼츠(shorts)AI가 추천한 구간 → 채택 시 클립.
팩토리(factory)소스 1건 → 분석·쇼츠·배포까지 자동 완주 파이프라인.
