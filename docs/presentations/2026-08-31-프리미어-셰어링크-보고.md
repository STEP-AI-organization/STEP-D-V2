> **판단이 필요한 자리는 "확인 필요" 로 적었다** — 안 돌려 본 것을 됐다고 적지 않았다.

## 0. 한 장 요약

| | 무엇 | 지금 상태 | 다음 한 걸음 |
|---|---|---|---|
| **A** | 프리미어 플러그인 | 패널 동작 · **파일럿(개발자 로드)** 단계 | `.ccx` 포장 → 편집자 PC 설치 |
| **B** | 쿠팡파트너스 셰어링크 | 파이프라인 전 구간 구현 · **프로덕션 게이트 ON** | 실제 회차로 한 바퀴(발급→검토→발행) |
| **C** | 토스쇼핑 셰어링크 | **계획만** (코드 없음) | Open API 사용 신청(심사 5영업일) |

**A 와 B 는 같은 목표의 양 끝이다.** A 는 편집자가 프리미어에서 안 나오게 하고,
B 는 발행되는 영상에 수익을 붙인다. 둘 다 "사람이 하던 왕복을 없앤다" 는 한 줄이다.

**C 를 지금 꺼내는 이유는 요율이다** — 쿠팡 실효 2% 미만 대 **토스 10%**.
같은 파이프라인에 채널만 하나 더 다는 것이라 추가로 만들 것이 많지 않다.

## A. 프리미어 플러그인

정본: [`packages/premiere/README.md`](../../packages/premiere/README.md) ·
추진안 [`docs/plans/active/premiere-plugin-plan.md`](../plans/active/premiere-plugin-plan.md)

### 무엇을 없앴나

편집자가 하루 두 번 하던 왕복 — **프리미어 나가기 → 브라우저 열기 → 파일 찾기 → 드래그**.
이걸 패널 버튼 하나로 접었다.

### 만든 것

Premiere Pro 안에서 도는 **UXP 네이티브 패널** (`packages/premiere/` · 948줄).

| 기능 | 설명 |
|---|---|
| 로그인 | STEP D 계정 그대로(웹과 같은 계정·같은 검증 경로) |
| 프로그램 선택 | 어느 프로그램의 회차인지 |
| **렌더해서 업로드** | 지금 타임라인의 시퀀스를 그 자리에서 렌더해 바로 올린다 — 원래 누르던 *내보내기* 를 이 버튼이 대신한다 |
| 파일 업로드 | 이미 렌더해 둔 완성본(폴백) |
| **추천 구간 탭** | 서버가 만든 추천을 패널에서 보고, 줄을 누르면 **플레이헤드가 그 구간으로 간다** |

업로드는 파일이 우리 서버를 거치지 않고 **패널 → 클라우드 저장소 직행**이다.
그래서 몇 GB짜리 완성본도 올라가고, 중간에 끊겨도 이어받는다.

### 설계에서 정한 것 둘

**① 게시는 웹에서만 한다.** 패널은 올리기까지만 하고 발행 버튼을 두지 않았다.
게시는 크레딧·승인·감사 기록이 걸린 문이라 문을 두 개 만들지 않는다.

**② 웹 화면을 안 만들고 패널에서 직접 그린다.** 처음 계획은 패널 안에 웹페이지를 띄우는
방식이었는데 접었다. 그러면 웹이 죽을 때 패널도 죽고, 로그인 상태를 두 런타임 사이로
넘기는 위험한 다리가 생긴다. 지금은 **웹 배포와 플러그인 릴리스가 서로 엮이지 않는다.**

### 만들면서 잡은 것

- **세션 만료 자동 복구** — 30분짜리 업로드를 끝낸 마지막 한 줄에서 로그인이 풀려
  전부 날아가는 게 가장 뼈아픈 실패다. 자격증명을 OS 키체인에 두고 그 자리에서 한 번
  다시 로그인해 이어간다.
- **`exportFull` 누락** — 이 인자를 안 넘기면 시퀀스 전체가 아니라 **작업 영역만** 나간다.
  편집자가 "다 올렸는데 앞부분만 올라갔다" 를 겪는 자리라, 찾아서 고정했다(커밋 204d0d3).
- **프레임 정합** — STEP D 는 원본 파일 0초 기준, 프리미어는 시퀀스 타임라인 기준이다.
  원본을 통째로 얹는 보통의 편집에서는 같지만, 시작 타임코드가 `01:00:00:00` 인 방송
  원본은 어긋난다. **아직 환산을 안 했고**, 대신 그런 회차는 목록에 `⚠ 프레임 정합 불가`
  라고 적는다 — 조용히 1프레임씩 틀리는 것보다 못 맞춘다고 적는 편이 낫다.

### 지금 단계와 남은 것

배포는 세 갈래이고 순서대로 밟는다.

| 단계 | 방법 | 심사 | 지금 |
|---|---|---|---|
| 1 파일럿 | 개발자 도구로 직접 로드 | 없음 | **여기** |
| 2 내부 배포 | `.ccx` 패키지를 편집자에게 전달 | 없음 | 다음 |
| 3 마켓플레이스 | Adobe Exchange 등록 | 있음(수 영업일) | 공개 배포를 원할 때 |

⚠️ **지금의 로드는 '설치' 가 아니다.** 그 PC 에서만 유효하고 프리미어를 껐다 켜면 다시
불러와야 한다. 편집자에게 넘기려면 2단계(`.ccx`)가 필요하다.

남은 것: 타임코드 환산 · 마커 일괄 생성 · macOS(렌더 프리셋 경로가 Windows 고정) ·
`.ccx` 포장. **개발용 도구(UDT) 설치 여부는 README 기준 2026-08-28 미설치 — 확인 필요.**

## B. 셰어링크 ① 쿠팡파트너스 — 구현 완료

정본: [`docs/ops/commerce-links.md`](../ops/commerce-links.md)

### 왜 만들었나

편집자에게 쇼츠 발행은 이미 일이다. 그 위에 "상품 찾기 → 링크 발급 → 대가성 문구 붙이기"
를 얹으면 **아무도 안 한다.** 실제로 아무도 안 해서 이 수익은 0원이 아니라 **존재하지
않았다.** 그래서 이미 돌고 있는 자동배포 경로에 얹었다.

### 흐름 — 사람이 하는 일은 "예/아니오" 하나

```
영상 분석 → 채택 → 메타 생성 ┬→ 제목·설명·태그
                              └→ 상품 검색어      ← 같은 호출에 얹음(추가 원가 ₩0)
                                    ↓
                            제휴 링크 자동 발급
                                    ↓
                    ★ 사람이 승인 (/commerce 화면) ★
                                    ↓
                    발행 직전에 설명란에 링크 + 대가성 문구
```

| 단계 | 누가 |
|---|---|
| 상품 찾기 · 링크 발급 · 문구 삽입 | 자동 |
| **어느 상품을 실제로 걸까** | **사람** (클립당 클릭 1~2회) |
| 파트너스 로그인 | 사람 (회사당 1회) |

### 설계에서 정한 것 셋

**① 발급 ≠ 게시.** 새로 발급된 링크는 전부 '대기' 다. 파이프라인이 상품을 잘못 골라도
(실측: 생화 꽃다발 장면에 드라이플라워) 방송사 채널로 바로 나가지 않는다.
**자동화가 노동을 지고 판단은 사람이 한다.**

**② 문구는 발행 직전에 붙인다.** 저장된 설명 본문에 굽지 않는다. 이유 둘 —
대가성 문구를 사람이 지울 수 없어야 하고(누락 = 계정 정지), 링크가 늦어도 발행이
안 막혀야 한다(링크가 없으면 원문 그대로 나간다).

**③ 상품 선택은 결정론이다.** AI 에게 순위·선별을 시키지 않는다 — 실행마다 결과가
바뀌면 측정할 수 없다. AI 는 "이 장면에서 뭘 사고 싶어질까" 를 **서술**만 한다.

### 돈이 새지 않게 한 것

**커미션 정산이 계정 단위라 회사마다 자기 법인 계정을 쓴다.** 계정을 잘못 고르면 A사
콘텐츠의 수익이 B사로 들어가는데, 이 실패는 **에러가 아니라 "발급 성공" 으로 보인다.**
그래서 방어를 셋 뒀다 — 데이터 격리 · 회사 대조 · **공용 계정 폴백 없음**(계정이 없으면
발급도 안 한다).

로그인 상태는 암호화해 보관하고, **키가 없으면 저장 자체를 거부**한다(평문 폴백 없음).

### 계정 정지와 직결된 안전 규칙

| 규칙 | 지키는 방식 |
|---|---|
| **발급한 링크를 절대 열지 않는다** (자기 클릭 = 즉시 정지) | 코드가 열지 않음 + 나가는 요청을 차단 + 소스 검사 + **화면에서도 링크가 아니라 '복사' 버튼** |
| 대가성 문구는 옵션이 아니다 | 링크가 있으면 항상 함께 나가고, 사람이 지울 수 없다 |
| 제휴 링크 형식만 통과 | 맨 상품 주소는 거부 — 정산이 안 돼 "링크는 걸렸는데 돈이 안 들어오는" 조용한 실패가 된다 |
| 확인된 채널만 | 지금은 YouTube 설명란만 |

> 실측으로 잡은 것 하나 — 콘솔에서 링크를 만들면 그 화면이 **미리보기 배너를 렌더하는데
> 그 자체가 제휴 이동**이라 클릭으로 집계될 수 있었다. 초기 실험 횟수만큼 리포트에 클릭이
> 찍혀 있었다. 지금 경로는 그 배너를 아예 안 띄운다.

### 운영·원가

- **온보딩**: 웹에서 '쿠팡 로그인 도우미' 를 받아 더블클릭 → 두 번 로그인 → 끝.
  (교차 출처 제약 때문에 웹만으로는 불가능해서 작은 실행파일을 내려준다)
- **원가 ₩0** — 상품 검색어는 기존 호출에 편승, 링크 발급은 브라우저 시간뿐.
  메타 품질 영향 없음(A/B 실측 · 상품 없는 장면은 빈 배열).
- 전용 PC 에서 돈다 — 한국 IP 가 필요하고, 화면 없는 브라우저는 차단된다(실측).

### 남은 것

| 항목 | 상태 |
|---|---|
| **실제 회차 한 바퀴** | 게이트 ON 상태로 발급→검토→발행 **아직 안 돌았다** |
| 공식 API 전환 | 최종승인(누적 판매 15만원) 대기 — 되면 전용 PC 의존이 사라진다 |
| 영상별 수익 회수 | 추적 축이 있는 것만 확인. 심으면 "어느 쇼츠가 얼마 벌었나" 가 나온다 |

### 냉정하게 — 쿠팡 단독으로는 크지 않다

쿠팡 실효 커미션은 **2% 미만**이다. 100만원어치를 팔아야 2만원이다.
쿠팡을 먼저 한 이유는 돈이 아니라 **길이 열려 있어서** 다 — 전 구간을 한 번 관통해
"장면에서 상품까지" 파이프라인을 세우는 게 목적이었다. 그 파이프라인이 지금 서 있다.

## C. 셰어링크 ② 토스쇼핑 — 계획

정본: [`docs/plans/active/toss-sharelink-plan.md`](../plans/active/toss-sharelink-plan.md)
· 코드는 **아직 없다.**

### 왜 다음이 토스인가 — 요율

| | 쿠팡파트너스 | **토스쇼핑 쉐어링크** |
|---|---|---|
| 커미션 | 실효 2% 미만 | **결제금액의 10%** |
| 전환 인정 | — | 클릭 후 **24시간** 내 결제 |
| 정산 | — | 월 단위 · 익월 25일 |
| 링크 발급 | 비공식 내부 API (브라우저 필요) | **공개 Open API** (서버 대 서버) |

**요율이 5배 이상이고, 발급 방식이 더 깨끗하다.** 쿠팡은 전용 PC 에서 브라우저를 띄워야
하지만, 토스는 서버에서 직접 부를 수 있어 그 PC 의존이 사라진다.

### 이미 있는 것 / 새로 만들 것

파이프라인 6단계 중 **5단계가 이미 서 있다.** 갈아끼울 곳은 상품·링크 부분뿐이다.

| 단계 | 쿠팡에서 만든 것 | 토스에 재사용 |
|---|---|---|
| 장면에서 상품 뽑기 | AI 가 검색어 추출 | ✅ 그대로 |
| 상품 고르기 | 결정론 규칙 | ⚠️ **바꿔야 한다**(아래) |
| 링크 발급 | 브라우저 자동화 | ❌ 새로 — 다만 **API 라 더 단순** |
| 사람 승인 화면 | `/commerce` | ✅ 그대로 |
| 발행 조립·대가성 문구 | 발행 직전 삽입 | ✅ 그대로 |
| 회사별 계정·오귀속 가드 | 있음 | ✅ 그대로 |

### 확인된 걸림돌 하나 — **검색 API 가 없다**

토스가 제공하는 조회는 카테고리 · 카테고리 베스트 · 하루특가 · 베스트 · 상품 상세 다.
**키워드로 상품을 찾는 API 가 없다.** 우리 파이프라인은 "장면 → 검색어 → 검색 → 상품"
이라 이 축이 그대로는 안 맞는다.

해법은 **상품 목록을 미리 받아 두고 검색어를 거기에 맞추는 것**이다. 다만 토스 운영정책이
"상품 데이터를 저장해 이커머스처럼 전시·가격비교하는 사이트" 를 승인 대상에서 빼고 있어,
**내부 매칭용 보관이 여기 걸리는지 심사 때 반드시 확인해야 한다.** 이게 이 계획의 최대 변수다.

### 착수 조건

1. **Open API 사용 신청** — 승인제다. 신청 → 심사 **영업일 5일** → 키 발급.
   승인 대상에 "게시 자동화 플랫폼" 이 명시돼 있어 우리 형태는 부합한다.
2. **출발지 IP 등록**(최대 10개) — 서버 IP 를 고정해야 한다.
3. 심사 때 함께 확인할 것: 위 상품 보관 가능 여부 · 회사별 계정 분리 방식 ·
   자동 발급 허용 범위.

**심사 통과 전에는 코드를 쓰지 않는다.** 위 답에 따라 설계가 갈리기 때문이다.

### 지켜야 할 것 (쿠팡과 같다)

- **경제적 이해관계 표시 의무 있음** — 상품 소개 근처에 눈에 띄게. 우리 구조는 이미
  발행 직전에 지울 수 없게 붙이므로 그대로 만족한다.
- **무효 클릭·자동 실행 금지** — 발급한 링크를 우리가 열지 않는 규칙을 그대로 적용한다.
