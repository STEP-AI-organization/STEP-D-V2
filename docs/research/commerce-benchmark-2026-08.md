## 1. 요약 (결론 먼저)

1. **AEDI-V가 파는 코어를 STEP D는 이미 갖고 있다.** `core/vision/ppl.py` 가 프레임 샘플링 →
   Gemini Vision → 브랜드·카테고리·노출구간(start/end)·confidence 를 `ppl.json` 으로 뽑는다.
   AEDI-V의 "시각 분석 + 타임스탬프 자동 등록"이 곧 이 산출물이다.
   **없는 것은 뒤쪽 절반** — 브랜드/카테고리를 실제 SKU 로 붙이는 *상품 카탈로그 레이어*.
2. **경쟁 지점을 크리에이터 툴로 잡으면 진다.** AEDI-V는 월 $9~28 셀프서브 B2C 가격대다.
   우리 자리는 그 층이 아니라 **권리를 가진 영상 라이브러리를 커머스로 바꾸는 B2B**다.
3. **우리의 유일한 구조적 차별점은 "불펌이 필요 없다"는 것.** SSMaker·윙디오의 프로세스는
   쿠팡파트너스 약관 위반이 명시적으로 걸린다(§3.3). 우리는 고객사가 권리를 가진 원본을 다룬다.
4. 먼저 확인해야 할 단 하나: **쿠팡파트너스 약관상 SaaS가 고객사를 대신해 제휴 링크를
   생성·운영하는 구조가 허용되는가**(대행 이슈). 여기서 막히면 설계가 통째로 바뀐다.

### 2.1 가격 앵커 — 이게 제일 실용적인 수확

AEDI-V의 과금 단위가 **분(minute) 크레딧**이다(30분/1시간/2시간). STEP D 의 `1크레딧 = 분석 1분`과 같은 단위다.

- AEDI-V Standard: $15.5 / 60분 ≈ **분당 약 360원**
- STEP D: 크레딧 **150원/분** (`4a345c4` 에서 ENA·세금 포함 확정)

즉 시장이 이미 분 단위 가격에 익숙하고, 우리 단가는 그 절반 이하다. 견적 협의 때 쓸 수 있는 외부 앵커.
단 원가는 회차당 ₩994(분당 약 ₩17)이므로 마진 계산은 `docs/ops/cost-and-dependencies.md` 기준으로 할 것.

## 3. STEP D 자산 대조 — 무엇이 이미 있고 무엇이 없나

### 3.1 이미 있는 것 (재사용)

| 모듈 | 현재 하는 일 | 커머스에서의 역할 |
|---|---|---|
| `core/vision/ppl.py` | 5초 간격 프레임 → Gemini Vision → 브랜드·카테고리·노출구간·confidence, 브랜드별 총 노출초 | **AEDI-V의 시각 분석 그 자체.** 상품 후보 추출기 |
| `core/search/embed.py` · `index_segments.py` | 세그먼트 임베딩·색인 | 상품 카탈로그를 같은 공간에 임베딩하면 대사·상황 기반 매칭(AEDI-V의 "음성/상황 분석") 대응 |
| `core/recommend/recommend.py` | 어느 구간을 숏폼으로 낼지 2단계 선별·스코어링 | 스코어에 **커미션 기대값** 한 항 추가하면 그대로 "커머스 숏폼 선별기" |
| `core/beats` · `reframe` · `thumbnail` | 컷·리프레이밍·썸네일 | 패스트컷/SSMaker가 파는 "영상 자동 생성"이 이미 파이프라인에 있음 |
| 자동 배포 규칙(`52a6560`) | 요일·시간 슬롯 기반 자동 발행 | 상품 시즌성·프로모션 일정과 붙는 지점 |
| 크레딧 원장 | 선불·append-only·402 선차단 | 1단계 커머스 과금을 그대로 얹을 수 있음 |

### 3.2 없는 것 (신규)

1. **상품 카탈로그 레이어** — 브랜드/카테고리 → 실제 SKU 조회, 제휴 링크 생성, 커미션율·예상수익 계산,
   품절·판매중단 모니터링. 통째로 없다. AEDI-V가 실제로 파는 건 사실 이쪽이다.
2. **성과형 정산 도메인** — 커미션 셰어는 선불 크레딧 원장(append-only, 차감형)과 방향이 반대다.
   1단계는 **크레딧으로만** 붙이고 성과형은 별도 도메인으로 미루는 게 맞다.
3. **테넌트별 제휴 계정 보관** — 쿠팡파트너스 ID·트래킹코드를 워크스페이스 단위로. API 키 보관 구조
   (sha256 + 접두 15자)를 재사용 가능.

### 3.3 지양 대상의 정확한 위험

SSMaker·윙디오식 "중국 숏폼 수집 → 재가공" 은 위 약관 조항에 정면으로 걸린다(복제·배포·전송).
제재가 경고가 아니라 **미지급 수익 몰수 + 계정 삭제**라는 점이 핵심이다.
기능(원스톱 자동화, 자막 블러, TTS)만 참고하고 **소스 수집 단계는 절대 따라가지 않는다.**
아이러니지만 AEDI-V 자체 블로그의 "계정정지 5가지 사유" 글도 같은 얘기를 하고 있다.

## 4. 포지셔닝 제안

> **크리에이터에게 상품을 붙여주는 툴이 아니라, 권리 보유 영상 아카이브를 커머스 자산으로 바꾸는 B2B.**

이미 `docs/stepd-core-and-future.md` 의 **"② 광고상품 자동 패키징"** 이 있다. 커머스는 그 쌍둥이다 —
같은 PPL 검출 산출물을, 광고영업(광고주에게 슬롯 판매) 대신 **어필리에이트(성과형 링크)** 로 수익화한다.
신규 파이프라인이 아니라 **기존 산출물의 두 번째 출구**로 설계할 것. (B2B 전략의 "API = 워크스페이스의
두 번째 입구" 와 같은 논리)

- 1단계(단면): 테넌트 내부. 방송사가 자기 아카이브에서 상품 노출 구간을 찾아 숏폼 + 제휴 링크로 자동 배포.
- 2단계(양면, Levanta 모델): 브랜드 ↔ 콘텐츠 보유사 매칭 마켓플레이스. 상한선이지만 양면시장이라
  지금 단계에서 손대면 이르다.

|---|---|---|
| R1 | **쿠팡파트너스 대행 가능 여부** | 파트너스는 개인·사업자 계정 단위다. SaaS가 고객사 대신 링크를 생성·운영하는 구조가 약관상 허용되는지가 설계 전제. **여기부터 확인** |

| R3 | 플랫폼 흡수 | 쿠팡 자체 AI·유튜브 공식 태깅이 계속 올라온다. 해자는 **영상 쪽(권리 있는 롱폼 → 구간 검출)** 에 둬야지 상품 쪽에 두면 밀린다 |
| R4 | 배포 채널 제약 | 현재 **YouTube 만 실동작**. 틱톡샵이 열려도 배포 경로가 없다 |
| R5 | 정산 모델 | 커미션 셰어 도입 시 원장 구조 변경 필요. 1단계는 크레딧 고정 권장 |
