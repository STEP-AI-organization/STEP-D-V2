## 판정

1. **성립한다 — 단, "맥락 상품" 레벨에서.** 기존 beats.json 텍스트만으로 회차당 5~6개
   구간이 쿠팡 검색 쿼리로 바로 변환된다. 추출은 LLM로 자동화 가능한 성격
   (서술→추출이므로 [llm-no-scoring 원칙]과 충돌 없음 — 순위·선별은 결정론으로).
2. **"화면에 나온 그 브랜드 그 제품"(PPL 레벨)은 이 데이터에 없다.** beats.json에 브랜드
   필드가 없고, 예능은 브랜드 블러 처리도 흔하다. 브랜드축이 필요하면 `core/vision/ppl.py`
   재실행 필요 — 58.6분 기준 ~703프레임 × 1,806tok ≈ 1.3M input:
   기본 모델(flash) ≈ ₩500, `GEMINI_PPL_MODEL=gemini-2.5-flash-lite` ≈ ₩180 (추정) · 10~15분.
   과다검출로 기본 OFF였던 이력 있음 — 커머스 용도로는 confidence·frames_hit 필터 재평가 필요.
3. **쇼츠 연결은 시간 조인이면 된다.** 추천/클립이 beat 정렬이므로, 클립 구간과 상품 구간의
   overlap으로 "이 쇼츠에 걸 상품"이 결정된다. 새 매칭 문제가 아니다.

②를 사람 없이 브라우저 자동화로 관통했다. Playwright + 실크롬(headed)으로 6개 쿼리 전부

₩0 · 6쿼리 ~1분. 스크립트는 세션 스크래치(`coupang-search-poc.mjs`), 프로토타입 단계라 리포 밖.

매칭 품질 (top-1 실물):

기술 실측 (프로덕션화 시 그대로 부딪힐 것들):
- **Akamai 봇차단 실재.** 순정 Playwright 크롬은 전 요청 "Access Denied". 우회 =
  `--disable-blink-features=AutomationControlled` + 홈 선진입(센서 쿠키 `_abck` 수집) 후 검색.
  취약한 우회이므로 저볼륨·캐시 전제. **쿠팡은 API 승인 후 공식 API로 대체하는 게 정도** —
  브라우저 자동화는 승인 전 임시 + 네이버(API 영구 부재)용.
- 검색 페이지 마크업이 구 `li.search-product` 카드가 아님 — 앵커 폴백으로 수집됐고
  이름·가격이 붙어 나온다. 프로덕션은 카드 파싱 재작성 필요.
- 같은 상품 중복 노출(옵션 차이) — URL 기준 dedupe 필요. 광고 상품 구분 미확인.

## ④ 파트너스 링크 발급 자동화 실측 (2026-08-26 · 최종승인 전 계정)

**전 체인 관통 완료.** 파트너스 계정 가입 직후(최종승인 전) 상태에서, 로그인된 크롬에 CDP로
붙어 **쿼리 → 파트너스 내장 상품검색 → 첫 상품 hover → '링크 생성' 클릭 → 단축 URL 회수**까지
사람 개입 없이 성공했다. 산출: `https://link.coupang.com/a/gwui1XI3B6` (에이센트 차량용 탈취제).
사람 몫은 **최초 로그인 1회**뿐 (전용 프로필 `%LOCALAPPDATA%\stepd\partners-chrome-profile`에
세션 유지).

구조적 발견 3개:

1. **쿠팡 본체를 긁을 필요가 없다.** 파트너스 콘솔 안에 상품검색이 내장돼 있고(쿠팡랭킹순,
   본체 검색과 top 상품 동일 확인), 검색→링크생성이 한 화면이다. 이 경로는 Akamai 차단도
   없었다 — 앞 절의 봇차단 우회는 이 경로를 쓰면 불필요해진다.
2. **내부 API 확보**: 링크 생성 시 콘솔이 `POST partners.coupang.com/api/v1/banner/iframe/url`
   를 호출한다. 프로덕션은 UI 클릭 대신 로그인된 브라우저 컨텍스트에서 이 엔드포인트를
   fetch(쿠키 동봉)하는 게 셀렉터 유지보수 없이 훨씬 견고할 것. (비공식 API — 언제든 바뀔 수
   있음, 저볼륨 전제)
3. **공식 대가성 문구가 링크 생성 화면에 명시**돼 있다: "이 포스팅은 쿠팡 파트너스 활동의
   일환으로, 이에 따른 일정액의 수수료를 제공받습니다." — 자동 삽입 기능(R2)에 이 문구
   그대로 쓰면 된다.

UI 자동화 실측 함정 (초기 접근 · **아래 API 계약으로 대체됨**):
- 카드의 '링크 생성' 버튼은 hover 오버레이라 평소 hidden — 텍스트 hover론 안 뜨고,
  좌표 기반 실제 마우스 이동+클릭이 필요했다.
- '상품정보' 버튼을 잘못 누르면 쿠팡 상품 탭이 새로 열려 CDP 페이지 선택이 엉킨다 —
  `partners.coupang.com` URL 우선 선택으로 방어.
- 생성된 제휴 링크는 **절대 열지 않는다** (자가 클릭 = 정지 사유). 회수는 DOM 읽기만.

## 콘솔 내부 API 계약 (2026-08-27 실측 · 구현의 실제 근거)

DOM 을 모는 대신 콘솔 트래픽을 떠 보니, 콘솔이 하는 일은 **fetch 두 번**이 전부였다.
현행 구현(`apps/server/src/coupang-partners.ts`)은 로그인된 페이지 컨텍스트에서 이 둘을
직접 부른다 — hover·좌표·셀렉터가 전부 사라져 유지보수 지점이 엔드포인트 2개로 줄었다.
쿠키·Akamai 센서값은 진짜 브라우저 것을 그대로 타므로 봇 차단에도 안 걸린다.

```
POST /api/v1/search
  {"page":{"pageNumber":0,"size":36},"filter":"<검색어>","deliveryTypes":[]}
  → {"rCode":"0","data":{"products":[{productId,itemId,vendorItemId,title,image,
      originPrice,salesPrice,deliveryBadgeImage,categoryId,ratingAverage,ratingCount,
      isAdult,isSoldOut,travel,...}]}}

POST /api/v1/banner/iframe/url
  {"product":{"type":"PRODUCT",itemId,productId,vendorItemId,image,title,
     originPrice,salesPrice,deliveryBadgeImage,travel:false}}
  → {"rCode":"0","data":{"shortUrl":"https://link.coupang.com/a/XXXX", ...}}
```

곁가지 관찰 (나중에 쓸 것):
- `GET /api/v1/subId/internal` → `["ha983885"]` — **subId 축이 이미 있다.** 영상별 성과
  추적(어느 쇼츠가 얼마 벌었나)을 붙일 자리다.
- `GET /api/v1/config` 응답에 `"openApiEnabled":true` — 공개 Open API 발급 가능 여부일 수
  있다. 사실이면 15만원 대기 없이 공식 API 로 갈 수 있다. **확인 필요**(UI 플래그일 수도).
- partners.coupang.com 에도 Akamai 봇 방어가 있다(`sensor_data`·`akam/13/pixel`) —
  서버에서 직접 HTTP 를 치면 막힐 가능성이 높다는 뜻이다. 브라우저 컨텍스트를 쓰는 근거.
- SPA 해시 라우트라 **같은 해시로 goto 하면 아무 요청도 안 난다**(캡처 0건). 재현하려면 reload.

### ⚠️ 구현에서만 드러난 버그 — `__name is not defined`

워커는 프로덕션에서도 **tsx(esbuild)** 로 돈다(`pnpm worker`). esbuild 의 `keepNames` 가
이름 붙는 함수마다 `__name(fn,"…")` 래퍼를 씌우는데, `page.evaluate` 는 함수를 **소스
문자열로 직렬화해 브라우저로** 보낸다 — 브라우저엔 그 헬퍼가 없어 전량 실패한다.
스크래치 PoC(순수 `.mjs`)는 멀쩡했고 유닛 테스트도 통과했다. **실제 모듈 스모크에서만
잡혔다** — 이 종류는 브라우저를 실제로 태워 보기 전에는 안 나온다.
대응 두 겹: ① 문자열 evaluate 로 `__name` shim 선주입 ② evaluate 콜백 안에 이름 붙는
내부 함수 금지(`commerce.test.ts` 가 소스 스캔으로 강제).
