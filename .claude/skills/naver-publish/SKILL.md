# 네이버 TV·클립 업로드

네이버는 **공개 업로드 API 가 없다.** 파트너 계약(SMR) 경로가 열리기 전까지 브라우저
자동화가 유일하다. 코드는 `apps/server/src/naver-tv.ts` · `naver-session.ts` · `naver-gate.ts`.

## 왜 클라우드가 아니라 사무실 PC 인가

**진짜 과제는 자동화가 아니라 세션 유지다.** 해외 데이터센터 IP(Cloud Run us-central1)로
로그인하면 캡차·2차인증에 막힌다. 그래서 네이버 잡은 한국 IP 의 **상시 PC 한 대**에서만
돈다 — GEBD 를 GPU VM 전용 레인으로 뺀 것과 같은 구조.

```bash
npx playwright install chromium                      # 1회 (~150MB)
pnpm --filter @stepd/server naver:login              # 사람이 로그인 (2차인증 포함)
WORKER_JOBS=naver NAVER_UPLOAD_ENABLED=1 pnpm --filter @stepd/server worker
```

`DATABASE_URL` 은 Cloud SQL 을 봐야 같은 `job_queue` 를 집는다.
세션은 `~/.stepd/naver-storage-state.json` — **머신 밖으로 내보내지 않는다**(쿠키 그 자체).

잡 페이로드: `{ clipId, target: "tv" | "clip", description, tags?, category?, publishAt? }`
(클립은 description·category 가 **필수** — 없으면 워커가 올리기 전에 실패시킨다)

## 게이트

`NAVER_UPLOAD_ENABLED` 가 명시적 truthy 일 때만 ON. 미설정·오타·빈값은 전부 OFF.
워커 진입 시 + 업로드 직전 2중으로 본다. 잘못된 env 의 실패 모드가 "업로드 안 됨"이어야지
"실수로 업로드됨"이면 안 된다.

## 클립 실측 구조 (2026-08-11)

**2단계다.** `/web/upload` 는 파일 드롭 화면뿐이고, 파일을 넣어야 같은 URL 에서 메타 폼이
렌더된다. 목록(`/web/contents/clips`)이 아니라 업로드 페이지로 직행할 것 — 목록에서
시작하면 "업로드 버튼 → 모달" 단계가 붙고 그게 개편에 제일 잘 깨진다.

| 항목 | 실측 |
|---|---|
| **제목 필드** | **없다.** 설명 300자 하나뿐 (`textarea[class^="ClipDetailForm_textarea"]`) |
| 태그 | 자유 입력 불가. 고정 버튼(장소·쇼핑·영화·공연·스포츠·게임·와인·제휴) |
| 콘텐츠 링크 | 블로그 · 네이버TV · 뉴스 중 **하나만** |
| 필수 | **설명(최소 10자)** · **카테고리 1차+2차** |
| 버튼 | `취소 / 임시저장 / 등록` |
| 1차 카테고리 | **40개** (플레이스·뷰티·푸드·일상·여행·패션·음악·반려 …) |

설명은 **배포 시점에 사람이 넣은 값이 최우선**이다. 제목을 앞에 덧붙이지 말 것 —
300자를 잡아먹어 사람이 쓴 문구가 뒤에서 잘린다. **10자 미만이면 등록이 막히는데 명확한
에러가 안 뜬다** — 올리기 전에 코드에서 거른다.

**커버·AI 활용·공개 설정·재생국가·댓글 허용은 건드리지 않아도 기본값으로 등록된다**
(2026-08-11 확인). 자동화할 필요 없다.

카테고리 트리거는 **문구로 잡으면 안 된다** — 선택 후 라벨이 고른 값으로 바뀐다.
`[class*="dropdownWrap"]` 순서(0=1차, 1=2차)로 잡는다. 옵션 매칭은 정확일치(`^…$`)로 —
`hasText` 는 부분일치라 "엔터" 가 "엔터테인먼트" 에도 걸린다.

기본 카테고리는 **1차·2차 모두 "엔터"** (`DEFAULT_CATEGORY`). 프로그램별 사전등록이
붙기 전까지의 임시값이다.

**등록 예약**(`publishAt`)은 공개 설정의 "등록 예약" 체크 + 날짜/시/분이다.
설정에 실패하면 **즉시 등록**되어 버리므로 그냥 넘어가지 않고 업로드를 중단한다 —
"예약한 줄 알았는데 바로 공개된" 실패가 제일 나쁘다.

## 함정 (전부 실제로 당한 것)

- **드롭다운 옵션은 `role=option` 이 아니다.** `[class*="Option"]` 으로 잡아야 한다.
  `li` 로 폴백하면 **사이드바 메뉴(대시보드·콘텐츠·커뮤니티·분석·수익)를 긁어서**
  카테고리가 5개로 나온다. 실제로 그 결과를 한참 들여다봤다.
- **파일 투입이 불규칙하다.** 숨은 input 에 `setInputFiles` 로 직접 넣으면 SPA 가 change
  이벤트를 못 받아 **조용히 1단계에 머문다**(에러 없음). 그래서 filechooser 우선 +
  input 주입 폴백 2중이다. 그래도 실패하면 스크린샷으로 화면 상태부터 확인할 것.
- **같은 파일을 짧은 시간에 반복 업로드하면 불안정해진다.** 네이버 스로틀링으로 보인다 —
  프로브 반복 시 파일을 바꾸거나 간격을 둘 것.
- **클래스 해시(`__bU_8J`)는 배포마다 바뀐다.** 접두사/부분 매칭이나 화면 문구로 잡는다.
- `page.evaluate` 에 화살표함수를 넘기면 tsx 가 `__name` 헬퍼를 주입해 깨진다 —
  **문자열로 넘길 것.**
- 콘솔 출력의 한글이 깨져 보이는 건 CP949 표시 문제다. 결과는 JSON 파일로 받아 확인한다.

## 프로브 (셀렉터가 깨졌을 때)

```bash
pnpm --filter @stepd/server naver:probe clip              # 1단계 DOM
pnpm --filter @stepd/server naver:probe clip <영상경로>    # 2단계까지 (실제 업로드됨)
pnpm --filter @stepd/server naver:categories <영상경로>    # 카테고리 1차→2차
```

산출물은 `~/.stepd/naver-probe/` (DOM 덤프 · 스크린샷 · JSON).
**등록/임시저장은 절대 누르지 않는다.** 그래도 업로드 자체는 되므로, 프로브 후 계정
콘텐츠 목록에서 발행 안 된 항목을 정리할 것.

## 실패 처리 방침

**자동 재시도를 하지 않는다.** 브라우저 자동화 실패는 대개 DOM 개편·세션 만료라 재시도해도
같은 결과고, 계정 잠금 위험만 키운다. 실패하면 `~/.stepd/naver-artifacts/` 에 스크린샷을
남기고 잡을 failed 로 둔다 — 사람이 그림을 보는 게 로그를 읽는 것보다 빠르다.

세션 만료는 별도 에러(`NaverSessionExpiredError`)로 구분한다. 재시도가 절대 의미 없는
상태라서다. 이때 `naver:login` 을 다시 돌리면 된다.

**자동 로그인은 시도하지 않는다.** 캡차·2차인증은 사람이 뚫어야 하고, 자동 시도는 계정
잠금만 부른다. 코드는 아이디·비밀번호를 아예 만지지 않는다.

## 약관

본인 계정·본인 콘텐츠라도 자동화 도구는 네이버 약관상 제한될 수 있고 계정 정지 리스크가
실재한다. 기술 판단이 아니라 사업 판단이다 — 게이트가 기본 OFF 인 이유이기도 하다.

## 미해결

- 2차 카테고리 전체 목록 미추출(파일 투입 불안정). 1차 40개만 확인 — 쓸 1차의 2차만
  사람이 확인해 프로그램 설정에 넣으면 된다
- 네이버 TV(`tv` 타깃) 셀렉터는 **미검증** — 클립만 실측했다
- 발행 1건 완주 실측 시간 없음 → 페이싱 값의 근거가 아직 없다
