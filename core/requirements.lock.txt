# core/ 파이썬 의존성 — **전이 의존성까지 포함한 재현용 전체 목록.**
#
# 워커 이미지(apps/server/Dockerfile.worker)는 `requirements.txt` 가 아니라 **이 파일로** 깐다.
# `requirements.txt` 는 "무엇을 왜 쓰는가"를 적는 사람용 목록이고, 여기는 "그래서 정확히
# 무엇이 깔리는가"다. node 쪽의 pnpm-lock.yaml 과 같은 역할이다.
#
# ## 출처 (2026-09-11)
#
# 지어낸 값이 아니다. **프로덕션에서 실제로 돌고 있던 워커 이미지**의 venv 를 그대로 떴다:
#
#   us-central1-docker.pkg.dev/step-d/stepd-server/stepd-server:content-20260911-1110
#   → /opt/corevenv/bin/pip freeze                                        (68개)
#
# "오늘 PyPI 가 주는 최신" 이 아니라 "실제로 회차를 완주해 본 조합" 을 고정한 것이다.
#
# ## 다시 만드는 법
#
#   # 1) requirements.txt 의 == 를 고친다
#   # 2) 깨끗한 컨테이너에서 풀어 본다 (호스트 venv 오염을 피한다)
#   docker run --rm -v "$PWD/core:/core" python:3.11-slim sh -c \
#     'python -m venv /v && /v/bin/pip install -q -r /core/requirements.txt && /v/bin/pip freeze' \
#     > core/requirements.lock.txt.new
#   # 3) 이 헤더를 다시 얹고 교체한 뒤, 워커 이미지를 빌드해 빌드타임 스모크를 통과시킨다
#
# ⚠️ **opencv 가 두 줄인 건 오타가 아니다.** scenedetect 가 opencv-python 을, mediapipe 가
#    opencv-contrib-python 을 각각 요구한다. 둘은 같은 cv2 디렉토리를 덮어써서 나중에 깔린
#    쪽이 이긴다 — 그래서 Dockerfile.worker 가 빌드타임에 cv2 가 4.x contrib 인지 검사한다.
#    자세한 사정은 requirements.txt 의 해당 주석에 적었다.
